# PRD2YTlist — PRD 转一堂清单体（v3.0）

## 一句话定位

把**权威源 PRD** 忠实转成**可扫读的一堂清单体**，并用**审计脚本 + 独立子智能体**做质量闸门，直到通过。

**两层转换**：`PRD 原文 → 清单体（Profile A）→ 32 字扫读版（Profile B）`。

### ★ 铁律优先级（不可颠倒）

> **① 语义一致 ＞ ② 单行 ≤32 字 ＞ ③ 版式美观**
>
> 三者冲突时**前者压后者**。
> **绝不允许为了凑够 32 字而删字、换词、丢限定词、丢否定词、合并语义、省略交叉引用。**

### 输出档位

| 档位 | 单行字数 | 形态 | 适用 |
|---|---|---|---|
| **Profile A** | ≤150 字（软，达标率 ≥80%） | 标准清单体 | 默认；评审/开发阅读 |
| **Profile B** | **≤32 字（硬，0 容忍）** | 32 字扫读版 | 需要逐行扫读 / 大屏走查 / 培训 |

Profile B **不是替换** Profile A，而是**叠加产出一版**（两者并存）。

### ★ 权威源声明（防止版本漂移）

- **判据 / 阈值 / 强度**：以**本文件（`SKILL.md`）为唯一权威源**。
- **正反例 / 长解释**：见 `references/yt-format-spec.md`（如有出入，**以本文件为准**）。
- **口径变更后**：必须**同步升 `references/` 与 `scripts/`** —— v2.x 曾因只升 `SKILL.md`
  导致 `references/` 停在 v1.x（70/50 口径，与 150 口径**差 2 倍严格度**）。

## 二、流程 S0 → S7

```
S0 定主题      一句话定位（≤60 字）+ 受众判断
S1 抽骨架      按「九类信息清单」扫描原文（Top-down）
S2 版式规划    ← 选择输出档位：Profile A（≤150）/ Profile B（≤32）
              定层级、标签；逐表判定 R5；逐节判定 R4（有序 or 无序）
S3 填充精修    填内容 → 分级字数校验 → 补浓缩标签
              ★ 收尾必做「重复前缀自查」（见下）
              （Profile B 下也先按 Profile A 做 —— 先保证语义完整，再切）
S4 自检        跑 scripts/audit_list.py（机械项）
S5 独立比对    ★硬闸门：子智能体验证语义完整度 ≥98%，不通过则回 S3
S6 32 字切分   ← 仅 Profile B；★ 每段必须 check_32 + audit_list --profile b 双脚本同跑
S7 回归比对    ← 仅 Profile B；★ 必做「否定词专项扫描」+ check_verbatim.py
```

### S3 收尾：重复前缀自查（v3.0 新增）

实测病灶：给一级点**加浓缩标签**时忘记删除原句首，产生**重复前缀**。

```
❌ 来源=…的记录：物料编码维度来源=…的记录：AVPL 在写入的同一时刻按…
✅ **来源="单据确定"的记录**：AVPL 在写入的同一时刻按…
```

→ 交付前搜一遍 `：.*：`（同一行出现两个冒号且前半段重复）与机械重复短语。

### S5 是硬闸门

`audit_list.py` / `check_32.py` / `check_verbatim.py` 只能查机械项（字数/层级/标签/锚点/表格单元格/逐字守恒），
**语义项（R4 判定、R5 的"该不该转"、信息完整度、限定词与否定词丢失）必须由独立子智能体复核**。
改造者不得自判通过。

**★ 机械闸门 ≠ 语义闸门（已三次实测验证）**：

| 案例 | 机械闸门结论 | 语义闸门结论 |
|---|---|---|
| PO v34 | 0 问题 | 仍抓出问题 |
| AVPL v12 · S4 → S5 | **0 问题**、锚点 0 失效 | **1 处整行遗漏 + 1 处标记失真 + 4 处措辞偏差** |
| AVPL v12 · S7 | — | **1 处否定词反转 + 4 处限定词丢失** |

### S6「只切不写」铁律（Profile B 专用）

**只做切分，不做改写** —— 不得增字、减字、换词、调序。

- **切分顺序**：`。` → `，` → `；` → `：`（长定义）→ `（）` 补语 → `、`（**最后手段**），与 R12 准则 2 一致。
- **装箱策略**：贪心填充至 ≤32，**优先保持原短语完整**（R12 准则 4/5）。
- **禁止**：为凑 32 字删限定词（希望 / 仅 / 不 / 全部 / 原始 / 批量 / 完整 / 统一）；省略「见 §X 节」；把精确数字换成约数。
- **必须**：**原文笔误原样保留**（如"本次差异**仅两点**"后实列 3 条的矛盾表述 —— 只登记，不改字）。

### S7 回归比对（Profile B 专用；S6 后有修正则必跑）

四步，缺一不可：

1. `scripts/check_verbatim.py <A稿> <B稿>` —— **R10/R11 逐字守恒**（V1~V6 精确串）。
2. **★ 否定词专项扫描**（**最高危**）：罗列 A 稿所有含「**不 / 未 / 无 / 非 / 禁止 / 不得 / 无需**」的句子，
   逐条确认 B 稿是否**保留否定语义**。
   - 实测：AVPL v12 全稿 **80+ 条否定句**，**1 条反转** ——
     「"价格过期"不展示任何操作（既**非**优势价格候选，也**不可**再手动失效）」
     → 被切成「**既是**优势价格候选**也**可再手动失效」，**语义 180° 反转**。
   - ⚠️ **这一条只有子智能体抓得到**（词频法无法命中，见冲突 18）。
3. **限定词与字段名扫描**：逐条比对「完整 / 统一 / 供应商 / 推送 / 批量 / 仅 / 不 / 全部 / 唯一 / 必须 /
   原始 / 过程 / 审批 / 落库」等，以及字段名与枚举值是否**逐字一致**。
4. 独立子智能体**回归比对**（G9），给出完整度与必修项。

## 四、已知规则冲突与处置（实战踩坑）

### 冲突 1：R5（表转清单体）× R3（字数上限）

- **现象**：长句表的单元格转到清单体后变成一条长点，**直接触发 R3 超限**。实测某篇 R3 违规数由 92 升至 123。
- **处置**：转清单体时**必须同步拆句**。Profile A 转出的行仍受 ≤150 约束；Profile B 直接按 ≤32 切。

### 冲突 2：R2 + R3 + R6 三者不可能同时满足

- **现象**：字段定义（字段名 / 说明 / 必填 三维度）若拆成 3 层满足字数，则违反 R6；若压成 1 行满足 R6，则违反 R3。
- **处置**：**字段定义类内容优先用「字段名（必填：X）：说明」单行式**；确需更长时允许该表**保留为表格**（R5 例外）。
- **Profile B 处置**：同上单行式（≤32），超长则**横向增标签**，不下沉。

### 冲突 3：R3 阈值对 PRD 偏严

- **实测**：一篇 393 行 PRD 的一级点平均 54 字、最长 116 字。
- **处置**：Profile A 下 R3 为**软约束**（阈值 **≤150**），报告「字数达标率」而非「违规数」，目标 **≥80%**。
- **Profile B 下不适用**（改为硬 0 超限，见冲突 5）。

### 冲突 4：R3 超限型复合句 —— 用 R9 拆二级治本

- **现象**：一级点冒号后堆了 2~3 个并列分句，字数直冲 180~200，靠**改写也压不下去**（压就丢信息）。
- **错误处置**：删字 / 砍信息 → **违反忠实性铁律**。
- **正确处置**：按 **R9 拆为二级子点** —— 信息零损失。
- **实测**：`计划协同承接EBS发运行_v14` 按 R9 拆 **21 处**后 R3 违规归零，**全文未删一字**。

### 冲突 5：★ R3 的两个数量级不可共存 —— 不是收紧，是替换

同一条 118 字的点在 R3（≤150）下**合规**，在 R3′（≤32）下超 **3.7 倍** → **违规**。
→ 处置：Profile B 下**替换**为 R3′，150 字阈值仅对 Profile A 有效。

### 冲突 6：★ R2「标签 4~6 字」× 32 字预算不可兼得

标签 14 字 + 冒号 = **吃掉 47% 预算**；缩成 4~6 字则**丢主语**。
→ 处置：**标签 ≤8 字**；**≥9 字保留原名、单独成行、内容全下沉**（分级强度见 R2′）。

### 冲突 7：★ R6 遭遇 32 字层级膨胀

32 字拆分把行数放大 2~3 倍，**层级压力必然上升**。
→ 处置：**横向增点优先于纵向嵌套**。实测：某篇无序行 310 → **1029**，但**层级全程 ≤3**。

### 冲突 8：★ R5「救单元格 vs 保结构」（**v3.1 已重新裁定**）

现象：`| 原型文件 | 计划协同_采购_原型_v11.html |` = **36 字** → 超 32。
v3.0 处置 = 把整张表转清单体；**实测代价过高** —— 一篇源稿 4 张表各仅 1 个单元格
踩线，却要拆掉 4 张完整表，列结构与行列对应关系全丢，且人为放大工作量与出错面。
→ **v3.1 处置：Profile B 正文表格一律照抄，不判单元格字数**；
 仅底部「待办事项 / 名词解释」两张表须转清单体。
 元信息表亦按「正文表格」处理 —— **照抄**，不再转清单体。

### 冲突 9：★ R9 被完全吸收（阈值成死条款）

R9 的阈值在 32 字下**永远自动满足**。
→ 处置：Profile B 下**阈值条款作废**，仅保留分组原则。实测：R9 建议项 **8 → 0**。

### 冲突 10：★ 质量闸门「软 / 建议 / 硬」三强度并存

同一件事（字数）在三处三种强度：**R3 软 · G8 建议 · R3′ 硬**。
→ 处置：统一为 **Profile A 软 / Profile B 硬**；**G8 作废**；**新增 G9 语义回归闸门**。

### 冲突 11：★「字数经济性不设目标」的度量基准被推翻

同段 120 字信息：Profile A = 1 行 × 120 字（1 次**长距**扫视 + **回扫**）；Profile B = 4 行 × 30 字（4 次**短距**扫视，**无回扫**）。
→ 字数一分未省，**变的是视线模型**。→ 指标从"总字数"换成 **「单行字数 P95 ≤32」**。

### 冲突 12：★ R1 只管"不加粗"、不管长度

`### 3.15 页面数据过滤条件调整与订单行状态筛选（本次调整）` = 正文 29 字 + `### ` = **33 字**。
→ 处置：**标题正文 ≤27 字**；变更标记移入正文 `- **变更属性**：…`。

### 冲突 13：★ 固定文案逐字保留 × 32 字

→ 处置：**引号内固定文案豁免 32 字**（R10 第 6 项），**但豁免只认「整行引号包裹」**（见 R10 严格口径）。

### 冲突 14：★ 引号豁免的"整行"约束（v3.0 新增）

加前缀就失去豁免：`- 全局轻提示："…"` 会被判超限，而
`- 全局轻提示：` + `  - "…"` 两行都过。
→ 处置：**长固定文案独占一行**；结构用「父标签 + 引号子点」。

### 冲突 15：★ 引用块 `> ` 不豁免（v3.0 新增，修复 v2.0 自相矛盾）

v2.0 的 R3 表写「目录项/引用块豁免」，`references` 的豁免速查表却写「引用块字数**不**豁免」——**同库互斥**。
实测口径（`check_32.py` 的 `visible()` 不剥 `> `）：
→ 处置：**引用块编号豁免、字数不豁免**，`> ` 的 2 字符计入 32 字。

### 冲突 16：★ S6 只跑一个脚本 → R6 延迟暴露（v3.0 新增）

实测：只跑 `check_32.py`（字数）没跑 `audit_list.py --profile b`（结构），
**33 处 R6（L5 层级超限）**直到合并后才暴露。
→ 处置：**S6 每段必须双脚本同跑**，两者职责不同、不可互替。

### 冲突 17：★ 否定词脱落 = Profile B 最高危病灶（v3.0 新增）

AVPL v12 S7 全场唯一一处**语义反转**出自「既**非**…也**不可**…」→「既**是**…也**可**…」。
→ 处置：**S7 必做「否定词专项扫描」**（见 S7 第 2 步）；G3 忠实度闸门增列该专项。

### 冲突 18：★ 词频差集不可用于丢失检测（v3.0 新增）

曾用「全局词频差集」做限定词扫描：AVPL v12 实测输出 **109 条候选，5 条真问题一条都没命中**
（长短语被切分后词频自然波动，信噪比极低）。
→ 处置：**弃用词频法**，只保留**精确串守恒**（`check_verbatim.py` V1~V6，实测 **1 条命中且可解释**）；
词级/语义级丢失**一律交独立子智能体**。

## 九、配套文件与脚本职责分工

### 脚本调用矩阵（**同一判据只由一个脚本负责**，避免双口径）

| 脚本 | 负责 | **不负责** |
|---|---|---|
| `scripts/check_32.py` | **字数**（Profile B 逐行 ≤32）+ 加粗跨行 | 结构、表格单元格 |
| `scripts/audit_list.py --profile b` | **结构**（R2 / R6 / R7；R5 单元格仅出**提示**） | **字数**（不判，避免冲突）；**正文表格单元格**（v3.1 起不判） |
| `scripts/audit_list.py --profile a` | 结构 + 字数（R1/R2/R3 软/R5/R6/R7/R9 建议） | — |
| `scripts/check_verbatim.py` | **R10/R11 逐字守恒**（V1~V6） | 语义 |
| `scripts/merge_segments.ps1` | 分段合并（UTF-8 无 BOM / 自动建目录 / **路径自愈**） | 校验 |
| **独立子智能体** | **语义**（R4 / 完整度 / **限定词与否定词**） | — |

### 快速命令

```powershell
S = ".codebuddy/skills/prd2ytlist/scripts"

# Profile A
python $S/audit_list.py  <稿> --profile a --detail

# Profile B —— 每段必须两个同跑
python $S/check_32.py    <段> --detail
python $S/audit_list.py  <段> --profile b --detail

# 合并（★ 用 -File 单独调用）
powershell -NoProfile -ExecutionPolicy Bypass -File $S/merge_segments.ps1 `
    -SegName "<简称>-32" -OutName "<模块>\<文件名>.md"

# 合并后必须在校验「合并稿」上跑 R7 锚点（分段稿跨段引用必然全红）
python $S/audit_list.py  <合并稿> --profile b --detail

# S7 回归
python $S/check_verbatim.py <A稿> <B稿> --detail
```

### ★ merge_segments.ps1 的编码根因（v3.0 已修）

v2.x 把**中文工程路径硬编码在脚本内**，并带中文注释。Windows PowerShell 5.1 会把
**无 BOM 的 UTF-8 `.ps1` 按 ANSI/GBK 解码**，后果有二：
① 硬编码的 `$base` 变乱码 → `Test-Path` 失败 → 误报"分段目录不存在"；
② **乱码注释字节直接把解析器搞崩**（`Unexpected token '}'`）。
旧规避方式是"必须单独一条命令执行"，属**治标**。
v3.0 改为**纯 ASCII 脚本 + 从 `$PSScriptRoot` / `Get-Location` 反推路径**，中文只经 argv 传入 —— **根因消除**。
