# PRD2YTlist 技能包一致性核对报告（v2.0 → v3.0）

> **核对日期**：2026-09-17
> **触发**：`AVPL v12` 全量跑实验（S0~S7）完成后，按「每个脚本和文件都要检查」要求做全包一致性审计
> **核对范围**：`SKILL.md`｜`references/yt-format-spec.md`｜`scripts/audit_list.py`｜`scripts/check_32.py`
> **结论**：**发现 27 项不一致 / 缺陷，全部已修**；另新增 2 个脚本，技能包由 4 文件扩为 6 文件

## 0. 核对方法

对技能包做**四向交叉比对**：

```
         SKILL.md  ←→  references/yt-format-spec.md      （跨文件口径）
              ↕                    ↕
      scripts/audit_list.py   scripts/check_32.py        （文档 ↔ 实现）
```

四条判据：

1. **同一判据在两处说法是否一致**（阈值 / 强度 / 档位）
2. **文档声称的机械能力，脚本是否真的实现**（"能查"必须真能查）
3. **脚本实现的判定，文档是否说清**（"会报"必须有依据）
4. **是否存在"只豁免、不校验"的空白**（放过 ≠ 确认原样）

## 7. 新增脚本：`check_verbatim.py`（V1~V6）

把 R10/R11 里**机械可判定**的部分做成 6 类**精确串多重集比较**。

| # | 校验项 | 对应规则 |
|---|---|---|
| V1 | 代码块（逐块内容，含缩进与空行） | R10-1 |
| V2 | 图片行 | R10-2 |
| V3 | 附件链接行 | R10-3 |
| V4 | 引号内固定文案（完整内容串） | R10-6 |
| V5 | 交叉引用编号 + `§x.y` 引用 | R11 |
| V6 | 目录章节号集合（**只比章节号，不比锚点串**） | 完整性 |

### ★ 方法选择：为什么不用词频法（重要教训）

先写了 `diff_tokens.py`（全局词频差集），AVPL 实测后**当场废弃并删除**：

| 方法 | 输出候选 | 命中已知真问题 | 判定 |
|---|---|---|---|
| 全局词频差集 | **109 条** | **0 条** | ❌ 弃用 |
| 精确串守恒（V1~V6） | **1 条** | 经核实**可解释**（冗余重复引用被清理，非丢失） | ✅ 采纳 |

**原因**：长短语在 32 字切分后被拆到不同行，词频**自然波动**，导致信噪比坍塌；
而精确串（引号文案、代码块、引用编号）**要么原样在、要么不在**，判据无歧义。

> **结论**：**限定词 / 否定词 / 语义级丢失无法机械化** —— 必须由独立子智能体做
> 「**否定词专项扫描**」。AVPL v12 全稿 80+ 条否定句，**唯一 1 条语义反转**
> （「既**非**…也**不可**…」→「既**是**…也**可**…」）**只有子智能体抓得到**。

## 8. `merge_segments.ps1` 编码根因修复

### 现象

v2.x 版本在「与其他命令用 `;` 串在同一条 `powershell -Command` 里」时，
必然报 **"分段目录不存在"**。团队当时的规避方式是记一条纪律：
**「本脚本必须单独一条命令执行」**。

### 根因（三层）

1. 脚本**把中文工程路径硬编码在自身**（`$base = "e:\...\SCC-需求变更清单体"`），并带大量中文注释；
2. Windows PowerShell 5.1 读取**无 BOM 的 UTF-8 `.ps1`** 时按 **ANSI（zh-CN = GBK）** 解码；
3. 后果有二：
   - 硬编码 `$base` 变乱码 → `Test-Path` 失败 → **误报"分段目录不存在"**；
   - **乱码注释字节直接把解析器搞崩** —— 实测报 `Unexpected token '}' in expression or statement`。

### 修复

| 措施 | 说明 |
|---|---|
| **纯 ASCII 脚本** | 脚本内**零非 ASCII 字符**（注释与提示全改英文），解码器如何工作**都不影响** |
| **路径自愈** | 从 `$PSScriptRoot` / `Get-Location` 向上走，并做 Depth 3 浅扫描，自动定位含 `data\segments` 的"阶段目录" |
| **自动建输出目录** | v2.x 缺失，曾因此报错 |
| **中文只经 argv 传入** | `-OutName "05-交付文件\…\xxx.md"` 由命令行传入，安全 |

### 验证

从技能包目录直接调用（**且不再是单独一条命令**）：

```
Merged -> …\05-交付文件\价格\AVPL\实验-20260917全量跑\_tmp_merge_test.md
segments: 11 | lines: 2718 | size: 130.8 KB
exit=0
```

→ 与项目内旧脚本的合并结果**完全一致**（2,718 行 / 130.8 KB）。
→ **「必须单独一条命令执行」的规避规则正式作废。**

### 9.1 ★ C1 修复的连带发现：全量 Profile A 回归暴露 3 处旧缺陷

对 `05-交付文件/` 下 **22 篇 Profile A 交付稿**（排除 `老版本/` 与 32 字版）跑 v3.0 `audit_list.py`：

| 结果 | 篇数 |
|---|---|
| **0 问题** | **21 / 22** |
| 报 `R3 = 3` | 1（`PO订单创建-PRD-v34.md`） |
| 仅提示（R9 宜拆 / R5 表格宜转） | 12 篇，**均不计入问题总数** |

`PO v34` 的 3 条 R3 明细：

| 行 | 位置 | 实测字数 |
|---|---|---|
| L575 | §4.2.4 订单检查结果 | **155 > 150** |
| L1203 | §4.3.9 数据与逻辑说明（后端） | **153 > 150** |
| L1649 | §5.1 术语说明 | **151 > 150** |

故**维持原稿不改**，仅在此登记。→ 若后续要收口，用 R9 拆二级即可（信息零损失）。
