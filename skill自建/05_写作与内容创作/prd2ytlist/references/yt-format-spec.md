## R1′ 标题（不加粗 + 长度）

- ✅ `## 3.1 全部订单列表——新增「订单备注」字段`
- ❌ `## **3.1 全部订单列表——新增「订单备注」字段**`
- ✅ 正文点内标签加粗**不算违规**：`- **位置**：…`

**Profile B 增补**：标题正文 **≤27~28 字**。

> **为什么是 27~28 而不是 28**：`check_32.py` 统计的是**整行可见字数**，含 `#` 前缀。
> 常用最深层级是 `#### `（5 字符），`### ` 是 4 字符。取 **≤27** 对任何层级都安全；
> 取 28 时 `#### ` 级标题必须恰好在 28 字以内。**建议统一按 ≤27 写**。

- ❌ `### 3.15 页面数据过滤条件调整与订单行状态筛选（本次调整）` → 正文 29 字，加前缀 = **33 字**
- ✅ 标记移入正文：
  ```
  ### 3.15 页面数据过滤条件调整与订单行状态筛选

  - **变更属性**：本次调整。
  ```
- ⚠️ 移入正文后**必须同步改目录锚点**（标题变了，锚点就变了）。
- 代价：会出现「有的标题带标记、有的不带」的风格不统一，**属可接受**。

## R2′ 点内浓缩标签

- ✅ `- **位置**：全部订单列表最后一列（合同名称列之后）。`
- ❌ `- 全部订单列表最后一列（合同名称列之后）。`（无标签）
- ❌ `- **这个字段的位置说明**：…`（标签过长）

### 一级点必须带标签（机械判定，**硬约束**）

`audit_list.py` 对**所有一级点**（有序 `1.` 与无序 `-`）强制要求 `**标签**：` 前缀，缺失即计 R2。

- ❌ **裸一级点**（小标题独占一行 + 裸 `- 内容`）——实测一次触发 27 处 R2：
  ```
  **全选逻辑**
  - 点击表头全选框：仅选中当前页中状态为「草稿」的行。
  ```
- ✅ **把小标题变成父点、内容下沉为 L2**（L2 不判标签）：
  ```
  - **全选逻辑**：
    - 点击表头全选框：仅选中当前页中状态为「草稿」的行。
  ```
- ⚠️ `- **标签**。`（标签后**没有冒号**）同样漏判 → **标签后必须有 `：`**（纯交叉引用短句 ≤12 字可豁免）。

### 标签长度：**分级强度**（v3.0 明确，消除重复惩罚）

| 情形 | 强度 | 落点 |
|---|---|---|
| 标签 ≤8 字 | 合规 | — |
| 标签 ≥9 字，且「标签：内容」**整行 ≤32 字** | **提示**（建议标签单独成行），**不计入问题总数** | `audit_list.py --profile b` 输出 `[R2] … 建议单独成行` |
| 标签 ≥9 字，且整行 **>32 字** | **必须**改为「标签单独成行 + 内容全下沉」 | `check_32.py` 报超限（硬） |

> **口径说明**：v2.0 曾把「≥9 字标签」一律判违规，导致 `**写入时机与操作角色**：见 3.4.2。`（共 17 字）这类**无害短行**被误报。
> v3.0 起硬约束**只由 32 字上限承担**，标签长度本身降为提示。

- ❌ 把「自动确认交期配置服务判断粒度」缩成「粒度」→ **丢主语，违反语义一致**
- ✅ ≥9 字且带长内容时，**保留原名单独成行**，内容全部下沉子点：
  ```
  - **自动确认交期配置服务判断粒度**：
    - 现状为逐条计划行独立判断是否满足条件。
    - 改造后改为订单行下全部计划行满足才批量转态。
  ```

- ✅

  ```
  - **可见范围**：…
  ```

## R3 字数上限（Profile A 软 / Profile B 硬）

| 位置 | Profile A | Profile B |
|---|---|---|
| 速读卡 | ≤50 | ≤32 |
| **正文点（一级点与子点）** | **≤150** | **≤32** |
| 表转行（由表格单元格转来） | 受 ≤150 约束（**原 ≤70 旧口径已废止**） | ≤32 |
| 目录项 | 豁免 | 豁免（**整行**豁免，含锚点） |
| 引用块 `>` | **编号豁免、字数不豁免** | **编号豁免、字数不豁免** |
| 表格内文字 | 单元格 ≤50（见 R5） | **不判**（正文表格照抄，见 R5） |

**强度**：Profile A **软** —— 报告「达标率」，目标 **≥80%**，**超限提示优化，不截断**；Profile B **硬** —— **超限行数必须为 0**。

> ⚠️ **v3.0 纠错**：v2.0 的 R3 表在「目录项 / 引用块」一行写了「豁免」，
> 而本文件末尾「豁免速查表」又写「引用块字数**不**豁免」——**同文件自相矛盾**。
> 实测口径（`check_32.py` 的 `visible()` 只剥缩进与列表标记、**不剥 `> `**）：
> **引用块的字数不豁免，且 `> ` 的 2 个字符也计入 32 字**。v3.0 统一为此口径。

### 超限的处置是「降级/拆分」，不是截断

- ❌ 截断：`- **位置**：全部订单列表最后一列（合同名称列之后）…`
- ✅ 降级为子点：
  ```
  - **界面展示**：动态字段，无数据时显示"-"。
    - 列宽跟随内容，不做超长截断处理（与列表其他文本列规则一致）。
  ```

### R3′（Profile B）计数口径 —— 必须写死

```
可见字数 = 原始行
         → 去行首缩进
         → 去列表标记（"- " 或 "1. "）
         → 去 markdown 标记（"**"、"`"）
         → 去链接 URL（保留链接文字）
         → 剩余字符数
```

中文按 1 字；英文 / 数字 / 符号各按 1 字；**空格计入**。

> ⚠️ **列表标记只剥 `- ` / `+ ` / `* ` / `1. `**。
> v2.x 的 `audit_list.py` 曾用 `^[-\d.\sa-zA-Z]+` 剥前缀，会把行首英文单词一并剥掉
> （`**ASL 推送状态**：…` → 从「推送状态」起算），导致 Profile A 的 R3 **系统性低估**。
> **v3.0 已修**。

> **两个数量级不可共存**：同一条 118 字的点，在 Profile A 下「合规」（≤150），在 Profile B 下超 **3.7 倍**（>32）。→ Profile B 下 **R3 的 150 字阈值被 R3′ 替换**，不是收紧。

## R4 标记规则（A+B 混合）

### A 类 → 无序 `-`

并列关系：属性 / 字段 / 规则 / 异常 / 清单。

- ✅ 后端五段（并列属性）
  ```
  - **数据实体**：本功能为 SCC 定制差异…
  - **关联关系**：与订单行为 1:1…
  - **数据来源**：值来自 SRM 订单主数据…
  ```
- ✅ 差异点清单、字段/枚举、规则清单、异常清单、诉求清单

### B 类 → 有序 `1.`

顺序关系：状态机 / 明确步骤 / 多步流程 / 记录生命周期。

- ✅ 按钮生命周期（状态机）
  ```
  1. **初始化条件**：输入框为空，按钮为默认可点击态。
  2. **触发指令**：点击「同步订单」按钮。
  3. **执行中**：按钮禁用 + 加载中…
  4. **执行结果**：弹窗展示成功/失败。
  ```
- **Profile B 增补**：有序点主干必须保持「**步骤名 + 一句话结论（≤32 字）**」，细节才下沉子点；否则 6 步法会变成 6 组 30+ 行，**顺序感反而下降**。

### 判定以内容为准，不以标题为准

- ⚠️ 标题 `### 3.4.2 交互逻辑与状态流转`，内容是「5 条并列联动规则」→ **判无序**。
- ⚠️ 标题 `### 3.9.2 交互逻辑与状态流转`，内容是「同一按钮的 7 步生命周期」→ **判有序**。
- ⚠️ AVPL v12 实测：`### 3.4.3 统一状态矩阵与互斥分组口径` 含状态矩阵（有序）**与**互斥分组判定（并列）两块 → **按块分别判定**，不要求整节统一。

## R5 表格判据

| 档位 | 规则 |
|---|---|
| **Profile A** | 文档元信息表**无条件保留表格**；其余表**任一单元格 >50 字** → 转清单体 |
| **Profile B** | **正文表格一律照抄，不判**；仅底部两张表须转清单体（见下） |

### ★ Profile B 口径（v3.1 修订：正文表格照抄）

**历史沿革**：v3.0 曾定「两步判据」（整行 ≤32 → 保留；否则逐单元格判，任一 >32 →
必须转清单体）。实测该判据**代价过高** —— 正文表格承载**列结构与行列对应关系**，
为救个别超长单元格而拆掉**整张表**会丢结构、并人为放大工作量与出错面
（实测一篇源稿 4 张表各仅 **1 个**单元格踩线，却要拆掉 4 张完整表）。

**v3.1 口径 —— 表格与图片 / 代码块同级，属「原样搬运」对象**：

| 对象 | Profile B 处置 |
|---|---|
| **正文表格** | **原封不动照抄**，单元格字数**不判** |
| **文档元信息表** | 按正文表格处理 —— **照抄** |
| **待办事项表 / 名词解释表**（底部两张） | **转清单体**：`- **事项/名词**：说明` |
| **图片 / 代码块** | **照抄**（`check_32.py` 已豁免） |

- **为什么只转底部两张表**：这两张表按定义不是「正文矩阵」，而是「条目 + 解释」形态，
  转成 `- **名词**：解释` 后**信息不损失**；而正文矩阵转清单体会丢列结构。
- **转换后不再受 R5 管**：转成的清单体行由 `check_32.py` 按常规 32 字约束。
- **脚本行为**：`audit_list.py --profile b` 对正文表格只出**提示**（列出 >32 字的
  单元格个数，供人工判断是否为底部两张表），**不计入问题总数** —— 即「不爆红」。
- **必须转换的举例**：`| 原型文件 | 计划协同_采购_原型_v11.html |` = **36 字**，
  若该表属底部两张表之一 → 转清单体：
  ```
  - **原型文件**：计划协同_采购_原型_v11.html。
  ```

### Profile A 的保留 / 转换

- **保留表格**（单元格均 ≤50 字）：文档元信息表、列定义表、字段定义表（短）、状态/枚举定义表、写入时机表、按钮启用条件表。
- **转清单体**（任一单元格 >50 字）：术语表、待跟进事项表、长句字段定义表、长句列定义表。

### 转换时必须同步拆句（关键）

- ✅ 或用「字段名（必填：X）：说明」单行式（Profile A 受 ≤150 约束；Profile B 超长则**横向增标签，不下沉**）

## R6 层级深度

| 档位 | 合规 | 提示（**不计入问题总数**） | 违规 |
|---|---|---|---|
| **Profile A** | ≤3 层 | **4 层**（容忍上限，建议收窄） | >4 层 |
| **Profile B** | **≤4 层** | — | **>4 层** |

> **Profile B 开放第 4 层级（2026-09-17 裁决）**：32 字切分天然把「父标签 → 分组 → 条目」加深一层，若强行压到 3 层反而会破坏语义分组，故开放第 4 层。**但第 5 层仍为违规。**

> ⚠️ **v3.0 纠错**：v2.0 的 `audit_list.py` 把 Profile A 的「4 层容忍」**计入问题总数**，
> 与 SKILL.md「容忍」的表述不符。v3.0 起 L4 统一降为**提示**，不计入问题总数。

### 横向增点优先于纵向嵌套

拆分前先问「**能不能变成兄弟标签**」，不能才下沉。

- 实测：某篇无序行 310 → **1029**（32 字版），但**层级全程 ≤3**。
- 实测（AVPL v12）：S6 首轮因未压层级，合并后一次报出 **33 处 R6（L5）**。

### 缩进口径

- 无序列点：**2 空格/级**（L4 = 6 空格）
- 有序点：`1.` / 3 空格 `- ` / 5 空格 `- ` / 7 空格 `- `

### Profile A 触发阈值

| 冒号后含 **≥2 个「；」**（≥3 段并列） | **必拆** |
| 冒号后含 **1 个「；」且可见字数 ≥80** | **宜拆** |
| 冒号后含 1 个「；」且 <80 字（短对照句） | **不拆**（拆了反而碎，如「仅同步日期/数量/备注；组织等沿用默认值」） |

### 分组原则（两档通用，**不是**机械地每个「；」各成一条）

1. **对照关系归为一组** —— 「现状 X；改造后 Y」算**一条**子点，不要拆开。
2. **主题切换处才拆开** —— 如从「现状/改造」切到「展示位置/展示形式」，另起一条。
3. 每段一条 `  - ` 子点，**保持原顺序**，**不加字、不减字**。

### 拆分写法

```markdown
- **同步状态/报错展示**：
  - 现状为无；改造后列表**不**新增"同步状态"列。
  - 同步结果**仅在"推送EBS"结果弹窗中展示**。
```

> ⚠️ **切勿去掉父点的 `-`**。若写成裸 `**标签**：` 段落，紧随其后的子点会被审计脚本判为**一级点**，触发 R2「一级点缺浓缩标签」。

- 实测（Profile A）：`计划协同承接EBS发运行_v14` 按 R9 拆 **21 处**后 R3 违规归零，**全文未删一字**。
- 实测（AVPL v12）：Profile A 全稿 R9 建议项稳定在 **13 项**，均属「宜拆」级，**不影响「0 问题」结论**。

## R10 豁免清单（Profile B 专用，不计入 32 字）

**以下内容一律「保留不处理」—— 不改写、不换行、不压缩：**

| # | 豁免对象 | 说明 |
|---|---|---|
| 1 | **代码块** | mermaid / plantuml / 其他源码 **逐字原样**，含 `\n` 换行符、括号、编号 |
| 2 | **图片** | `![alt](src)` 整行保留 |
| 3 | **附件链接** | `[附件：xxx](path)` 等文件引用整行保留 |
| 4 | **目录项** | 含 `](#` 的行（缩写会切断锚点） |
| 5 | **一级标题** | `# ` 开头的文档主标题（`## ` 及更深标题**仍计入**） |
| 6 | **引号内固定文案** | 提示语 / 按钮文案 / 空态文案 —— **逐字保留**，即使略超 |

> 除豁免项外，**其余所有正文行（含标题）均须 ≤32 字**。

### ★ 引号豁免的严格口径（v3.0 新增，来自 AVPL 全量跑实测）

第 6 项的判定**不是「含引号就豁免」**。必须同时满足三条：

1. 可见文本**首字符**是 `"` `「` `『`
2. **末字符**是配对的 `"` `」` `』`（其后可跟一个句末标点 `。.！!？?`）
3. **去掉首尾引号后的中间部分，不得再出现任何引号**

- ❌ **实测反例**：`- "已取消优势价格，该物料当前无优势价格，PR 匹配将按最低价执行"。`
  → 末位是 `。`，剥掉首尾后中间**仍含结束引号** `"` → **不豁免** → 报 **34 字**。
- ✅ **修正**：去掉句末 `。`，让引号成为整行末尾 → 豁免通过。

> **推论（务必遵守）**：**Profile B 的长固定文案必须独占一行**
> ```
> - 全局轻提示：
>   - "已取消优势价格，该物料当前无优势价格，PR 匹配将按最低价执行"
> ```
> `文案：` / `提示：` / `弹窗文案：` / `追加提示：` 等前缀**一律不能与引号同行** ——
> 否则前缀会计入 32 字，导致本可豁免的文案被判超限。

### ★ 引用块 `>` **不在豁免清单内**（v3.0 强调）

`check_32.py` 的 `visible()` 只剥行首缩进与列表标记，**不剥 `> `**，故：

- `> ` 的 **2 个字符计入 32 字**；
- 长引用块必须**拆成多行 `> `**，或**转成 `- **标签**：` 清单体**。

实测（AVPL v12）：全稿 **11 行引用块**，其中 2 行超 32 字，均由脚本报出后拆解通过。

## R11 不可断行单元

以下内容**不得被切分到两行**（切了即失真）：

- 交叉引用：`§3.13.1`、`§3.9～§3.12`
- 数字 + 单位 / 区间：`0～365`、`2026/10/8`、`超 180 天`
- 格式串：`YYYY/M/D`、`"; "`、`#4996B8`
- 引号内文案：`"网络异常，请重试"`
- 字段枚举串：`执行中、撤销、冻结、交货已完成`（可整串下沉为一条子点）

> **机械化校验**：`scripts/check_verbatim.py` 会比对 A/B 两稿的**交叉引用编号集合**，
> 某编号在 B 稿缺失即报错（实测 AVPL v12 仅 1 条命中，且经核实为**冗余重复引用被清理**，非丢失）。

## R12 切分与装箱五准则（Profile B 专用）

**背景**：S6 实测踩坑 —— 把「装箱」做成了「逐标点拆段」，产出两类坏行：
① `**加粗**` 被撕成两行（**markdown 渲染损坏**）；② 语义被切碎，可读性反而下降。

| # | 准则 | 说明 |
|---|---|---|
| 1 | **一个语义单元 ≤32 就独占一行** | 不得再把完整的「标签：+ 结论」拆开 |
| 2 | **切点只用标点** | 优先级 `。` → `，` → `；` → `：` → `（）` → `、`；**无标点不得硬断**——整段无标点且 >32 时，才切在并列连词「或 / 和 / 及」处 |
| 3 | **`**…**` 不可跨行** | 加粗片段必须完整落在一行内；挤不下就把「**标签**：」单独提行，让加粗整体落到下一行 |
| 4 | **装箱 = 在「标点片段」之上贪心合并** | 不是「把每行塞满到 32」。宁可某行短，也不要为填满而在无标点处硬断 |
| 5 | **不跨标签合并** | 贪心合并**只发生在同一个「标签：+ 内容」单元内部**；不同标签是不同语义单元，**不合并**（否则一行会出现两个标签） |

> ⚠️ **v3.0 纠错**：v2.0 正文标题写「**四准则**」，表格里却有 **5 条**。
> 另：准则 2 的切点优先级含 `，`，而 SKILL.md 的 S6 切分顺序漏了 `，`。
> v3.0 统一为：**`。` → `，` → `；` → `：` → `（）` → `、`（最后手段）**。

**正反例（S6 实测）**

- ❌ **加粗跨行**（渲染损坏）
  ```markdown
  - 成功条件：**只有推送逐行匹配结果全部成功，
  - 订单才真正进入「已审批」**。
  ```
- ✅ **标签提行，加粗完整**
  ```markdown
  - 成功条件：
  - **只有推送逐行匹配结果全部成功，订单才真正进入「已审批」**。
  ```
- ❌ **切在词中**（两侧都不成句）
  ```markdown
  - 变更单：版本 2 及以后的变更单不会修改
  - SRM订单号或 EBS订单号，仅版本号递增。
  ```
- ✅ **切在并列连词处，两侧词形完整**
  ```markdown
  - 变更单：版本 2 及以后的变更单不会修改 SRM订单号
  - 或 EBS订单号，仅版本号递增。
  ```
- ❌ **跨标签合并**（一行出现两个标签）
  ```markdown
  - **草稿**：视觉：灰色。
  ```
- ✅ **标签提行**（父标签与子标签各占一行）
  ```markdown
  - **草稿**：
    - 视觉：灰色。
  ```

> **与铁律的关系**：准则 1 是铁律 ①「语义一致 ＞ ② 单行 ≤32」的落地方式 —— 满足 32 字应当靠**换切分单位**（标签提行 / 换标点切点），**不是靠把句子撕碎**。

> **机械化校验**：`scripts/check_32.py` 已内置「加粗跨行」检测（行内 `**` 计数为奇数即报错），与字数超限并列计入返回值。

> **实测效果（PO订单创建 v34 · §1~3 段）**：同内容按 R12 重切 —— 计数行 **149 → 138（−7.4%）**、平均可见字数 **17 → 19（+11.8%）**、≤16 字短行 **64 → 49（−23.4%）**、以 `、，；：` 结尾的碎片行 **73 → 62（−15.1%）**，超限与加粗跨行**均保持 0**。→ R12 的收益是**减少碎片、提高单行信息密度**，而非大幅压缩行数。

## §13 脚本职责分工与调用矩阵（v3.0 新增）

**核心原则**：**同一个判据只由一个脚本负责**，避免"双口径"。

| 脚本 | 负责 | **不负责** |
|---|---|---|
| `scripts/check_32.py` | **字数**（Profile B 逐行 ≤32）+ 加粗跨行 | 结构、表格单元格 |
| `scripts/audit_list.py --profile b` | **结构**（R2 标签 / R5 表格单元格 / R6 层级 / R7 锚点） | **字数**（已改为不判，避免与 check_32 冲突） |
| `scripts/audit_list.py --profile a` | **结构 + 字数**（R1/R2/R3 软/R5 单元格 ≤50/R6/R7/R9 建议） | — |
| `scripts/check_verbatim.py` | **R10/R11 逐字守恒**（代码块 / 图片 / 附件链接 / 引号文案 / 交叉引用 / 目录章节号） | 语义、限定词 |
| `scripts/merge_segments.ps1` | 分段落合并（UTF-8 无 BOM、自动建目录、路径自愈） | 校验 |
| **独立子智能体** | **语义**（R4 判定 / 信息完整度 / 限定词与**否定词**丢失） | — |

**标准 S3~S7 调用序列**：

```powershell
# Profile A 每段 / 每稿
python scripts/audit_list.py <稿> --profile a --detail

# Profile B 每段 —— 两个脚本必须同跑（只跑一个会漏掉整类问题）
python scripts/check_32.py <段> --detail          # 字数
python scripts/audit_list.py <段> --profile b --detail   # 结构

# Profile B 合并后（R7 锚点必须在校验合并稿上跑，分段稿跨段引用必然全红）
powershell -File scripts/merge_segments.ps1 -SegName "<简称>-32" -OutName "<模块>\<文件名>.md"
python scripts/check_32.py <合并稿> --detail
python scripts/audit_list.py <合并稿> --profile b --detail

# S7 回归
python scripts/check_verbatim.py <A稿> <B稿> --detail
```

### ★ 两条硬性纪律（AVPL v12 全量跑实测教训）

1. **S6 每段必须两个脚本同跑**。实测只跑 `check_32.py` → **33 处 R6（L5 层级超限）**延迟到合并后才暴露。
2. **`merge_segments.ps1` 必须用 `-File` 方式单独调用**（不要与其他命令用 `;` 串在同一条 `powershell -Command` 里）。
   根因是 PowerShell 5.1 按 ANSI/GBK 解码无 BOM 的 UTF-8 `.ps1`；v3.0 的脚本已改为**纯 ASCII + 路径自愈**，
   从根上消除，但**跨命令串写仍建议避免**（会污染 `Get-Location`）。

## §12 逐字守恒闸门 V1~V6（v3.0 新增）

`check_verbatim.py` 把 R10/R11 里**机械可判定**的部分做成 6 类**精确串多重集比较**：
A 稿（基准）中出现过的精确串，B 稿（待验）中必须原样存在。

| # | 校验项 | 对应规则 |
|---|---|---|
| V1 | **代码块**（逐块内容，含缩进与空行） | R10 第 1 项 |
| V2 | **图片行** | R10 第 2 项 |
| V3 | **附件链接行** | R10 第 3 项 |
| V4 | **引号内固定文案**（完整内容串，直/弯引号均收） | R10 第 6 项 |
| V5 | **交叉引用编号 + `§x.y` 引用** | R11 |
| V6 | **目录章节号集合**（**只比章节号，不比锚点串**） | 完整性 |

> **为什么 V6 不比锚点串**：Profile B 按 R1′ 缩短标题后，锚点**必然**变化。
> 逐串比对会产出大量**预期内噪声**（AVPL v12 实测 21 条）。
> 锚点有效性本身由 `audit_list.py` 的 **R7** 在**同一份文件内部**校验。

**AVPL v12 实测信噪比对照**（这是 v3.0 采纳精确串法、放弃词频法的直接依据）：

| 方法 | 输出候选 | 命中已知真问题 | 判定 |
|---|---|---|---|
| 全局词频差集 | **109 条** | **0 条** | ❌ 弃用 |
| 精确串守恒（V1~V6） | **1 条** | 经核实**可解释**（冗余重复引用被清理，非丢失） | ✅ 采纳 |

> **结论**：**限定词 / 否定词 / 语义级丢失无法机械化** —— 必须由**独立子智能体**
> 做「**否定词专项扫描**」。实测 AVPL v12 全稿 80+ 条否定句，**1 条反转**
> （「既**非**优势价格候选，也**不可**再手动失效」→「既**是**…也**可**…」），**只有子智能体抓得到**。
