# PRD 插入规则

在目标 PRD Markdown 中插入 UML 源码链接与更新附录的标准方法。

## 一、正文链接插入

在用户指定的章节中，找到合适位置（通常紧随该章节已有的图片引用之后），插入：

```markdown
> 📎 UML 源码：[[源文件名]]
```

其中 `源文件名` 为封装 MD 去 `.md` 后的名称，如 `[[供应商分级.drawio]]`、`[[供应商分级产品架构图.eddx]]`。

**定位规则**（按用户提供的章节信息依次匹配）：
1. 用户明确给出章节标题（如 `#### 供应商分级产品结构图`）→ 用 `grep -n "章节标题" PRD文件` 定位
2. 用户给出相对位置（如"在 X 章节之后"）→ 找到 X 章节结束位置（下一同级/更高级标题前）插入
3. 用户只给 PRD 文件 → 询问插入章节（状态 2 处理）

## 二、附录 A：目录结构

在 `## 附录` → `### A. 目录结构` 中：

1. 代码块 `md版本文档整理/` 的树状列表中加入 `{源文件名}`（不含 .md）
2. wikilink 列表中加入 `- [[{源文件名}]]`

**注意**：树状列表与 wikilink 列表两处都要加，保持一致。

## 三、附录 C：图片 → UML 映射表

在 `### C. 图片 → UML 映射表` 表格末尾新增一行：

```
| [[{源文件名}\|{源文件名}]] | {源文件名}（源文件） | — | {图类型} | {格式} | [[{源文件名}]] | ✅ 通过 |
```

- 图类型如：页面流转图 + 状态图 / 系统架构图（四阶段分层）
- 格式如：Mermaid / PlantUML

## 四、附录 D：转换元数据

更新：
- `转换时间`：当前 ISO 8601
- `迭代版本`：iteration N → iteration N+1

## 五、附录 E：已知问题（如有）

若转换存在无法自动处理的项（如流程图无文本无法还原、结构不清晰），追加记录行：
`| {序号} | {位置} | {问题描述} | {建议处理} |`

## 六、目录一致性

正文中每插入一个 `> 📎 UML 源码：[[xxx]]`，必须同时保证：
- 附录 A 树状列表 + wikilink 都有该文件
- 附录 C 映射表有该行
- 附录 D 迭代版本 +1

三者缺一不可，完成后再向用户汇报。

## 七、命名约定

| 源文件 | 封装 MD 文件名 | wikilink |
|---|---|---|
| `xxx.drawio` | `xxx.drawio.md` | `[[xxx.drawio]]` |
| `yyy.eddx` | `yyy.eddx.md` | `[[yyy.eddx]]` |
| `zzz.xmind` | `zzz.xmind.md` | `[[zzz.xmind]]` |
| 图片 `aaa.png` | `aaa.md` | `[[aaa]]` |

文件名必须沿用源文件原名并保留扩展名，不得改名。
