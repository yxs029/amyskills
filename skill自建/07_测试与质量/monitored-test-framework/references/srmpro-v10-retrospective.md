## 一、踩坑信息清单（按严重度排序）

### 坑1【致命】vxe-table vs el-table 选错，全模块FAIL
- **现象**：M04-M10共44个用例全部FAIL，错误信息全是 `Timeout 30000ms exceeded. waiting for locator(".el-table__row")`
- **根因**：AI根据功能描述**猜测**CSS选择器，图纸库实际用vxe-table组件（class=`.vxe-body--row`），不是Element UI的el-table
- **解决**：写 `debug_empty_list.py` 5秒定位真实组件（`page.evaluate('document.querySelector(".el-table__row, .vxe-body--row, .ant-table-row").length')`）
- **教训**：全模块全FAIL + 错误信息都是选择器超时 = 100%是猜选择器，必须先探索真实DOM再写脚本

### 坑2【致命】3个0步ERROR用例（v9遗留）
- **现象**：M04-007、m08_tc03、m08_tc07三个用例steps=0/shots=0
- **根因**：
  - M04-007: 变量`close_menu`未定义（拼写错误导致脚本崩溃）
  - m08_tc03: 变量`statuss`拼写错误
  - m08_tc07: `len(None)` 类型错误（列表变量为None）
- **解决**：v10补测脚本用try/except + 三件套（关闭菜单/确认弹窗/操作记录），保证每个用例跑出步骤
- **教训**：测试脚本里的辅助变量命名要和DOM验证保持一致；用`.get('steps',[])`代替直接索引避免NoneType

### 坑3【重要】5个1步浅用例 = 真实系统问题
- **现象**：5个用例steps=1，应该是脚本偷懒
- **实际**：review后发现是**真Bug**（按钮找不到/字段为空/弹窗无响应），不是脚本问题
- **解决**：保留FAIL标记（带具体实际值），不强行补深到PASS
- **教训**：浅用例 = 系统Bug信号，不是脚本Bug。补深时要先判断"实际值是否正常"

### 坑4【重要】侧边栏菜单不展开
- **现象**：截图后看菜单只有"首页"
- **根因**：RuoYi框架默认折叠二级菜单，必须点击展开按钮
- **解决**：登录后先 `page.locator('.sidebar-toggle-btn').click()` 展开菜单再截图
- **教训**：截图前要先确认DOM状态完整，不只是"页面打开"就算完

### 坑5【重要】批量归档性能6秒>3秒
- **现象**：勾选5个图纸→批量归档→耗时6.01秒
- **根因**：后端处理N个归档是串行的，不是批量接口
- **解决**：P1提单到云效
- **教训**：性能Bug常常藏在批量操作里，要计时对比

### 坑6【一般】菜单"保存配置"是主题设置，不是业务配置
- **现象**：点图纸库页面的"保存配置/重置配置"按钮，发现是RuoYi主题面板
- **根因**：UI框架和业务功能用了相同按钮名
- **解决**：老大给了正确URL `/system/moduleconfiguration/drawConfig` 才找到图纸库配置
- **教训**：路径/菜单名相似时，要看URL不能只看UI文本

### 坑7【一般】上一次的归档操作让下次的列表变空
- **现象**：v10补测时，行数=0，所有操作失败
- **根因**：M07测试时把所有数据归档了，没恢复
- **解决**：补测脚本开头先批量"恢复"所有归档数据
- **教训**：测试脚本需要"清理"步骤，否则会污染环境

### 坑8【一般】文件上传DOM结构多版本（vxe-uploader vs el-upload）
- **现象**：M03上传脚本找不到file input
- **根因**：实际是vxe-uploader组件，结构是 `input[type=file][style="display:none"]`
- **解决**：用 `page.evaluate('document.querySelectorAll("input[type=file]")')` 搜索全部页面file input
- **教训**：上传组件跨多个UI框架，类型都是input[type=file]，但选择器路径不同

## 二、踩坑后怎么解决

### 解决模式1：假设思维5步法
1. **列假设**：登录失败可能是滑块/按钮disabled/cookie失效
2. **逐条验证**：分别测试robust_login/storage_state/smart_login
3. **跑通的归档P层**：robust_login成功→写入skill `qa/srmpro-login`
4. **跑不通的换下一条**：storage_state放弃
5. **全跑不通换模块**：登录卡3小时→先做M08-M10能登录的模块

### 解决模式2：debug脚本5秒定位
- 不直接重写脚本，先写 `debug_xxx.py` 探索真实DOM
- 用 `page.evaluate('...')` 取DOM快照，截图佐证
- 真实DOM搞清楚了再写正式测试脚本

### 解决模式3：分批+追加模式（防崩溃）
- 长测试批次分批跑（BATCH_START/BATCH_END）
- 每批保存中间结果到独立文件名（避免覆盖）
- 全部跑完后从日志用正则 `\[(PASS|FAIL)\] (TC-\S+) - (.+?): (.+)` 合并
- **教训**：绝对不能用单一JSON文件分批保存

## 三、怎么监督测试到底有没有测过

### 监督维度1：步骤深度（防假阳性）
- **规则**：steps≤1 或 shots=0 的PASS不可信
- **审计**：v10复盘发现 128用例中 27用例=4步/63用例=3步/24用例=2步/5用例=1步/3用例=0步
- **结论**：82.4%用例≥3步达标，5个1步+3个0步已补深或保留FAIL

### 监督维度2：截图覆盖（防"假装执行"）
- **规则**：每个步骤必须带base64截图
- **审计**：362张截图 / 128用例 = 2.83截图/用例
- **结论**：96.2%用例有截图（122/128）

### 监督维度3：DOM断言返回值（防"截图骗人"）
- **规则**：每个步骤必须带具体数值（行数/字段值/状态），不能只说"成功"
- **审计**：v10用例actual字段全部含具体数值（如"已过期筛选: 前=10->筛选=10"）
- **结论**：所有用例都有"动作→结果"的明确数据链路

### 监督维度4：进度可见性
- **机制**：后台进程+tee日志+定时poll
- **实践**：9个脚本全部后台跑，session_id追踪，输出到 /tmp/*.log
- **教训**：必须有实时输出，否则无法判断是卡死还是慢

### 监督维度5：交叉验证（多人多角色）
- **机制**：用aarontest普通用户+admin管理员两个账号交叉跑权限用例
- **实践**：M07供应商文档库S015/S017分别用testadmin/admin测菜单可见性
- **结论**：发现P0级菜单权限缺失Bug（普通用户看不到供应商文档库）

## 四、DOM关联 + DOM断言 + 截图一体化

### 当前截图组成
每张截图含3层信息：
1. **像素层**：截图本身（PNG base64）
2. **DOM层**：DOM断言返回值（行数/字段值/状态文本）
3. **监控层**：监控子智能体旁路验证（独立进程截图对比）

### 截图证据链
```python
step = {
    "step": 1,
    "action": "点击已过期统计卡片",
    "result": "列表行数从 20 → 10",
    "ok": True,
    "screenshot": "iVBORw0KGgo..."  # 100KB base64
}
```

### DOM证据设计（待改进）
当前只记了行数等浅层数据，建议扩展为：
```
{
  "dom_snapshot": {
    "component": "vxe-table",
    "rows": 20,
    "columns": ["文件名","版本","有效期","操作"],
    "cell_values": [["TI-001.pdf","v1","2026-12-31","查看|更新|归档"]]
  },
  "dom_assertion": {
    "selector": ".vxe-body--row",
    "expected": ">=1",
    "actual": 20
  }
}
```

### 视觉证据优化点
- 当前截图只标"步骤1截图"，应该标注关键DOM元素位置
- 应在截图上叠加红框/箭头指向断言对象
- 应在截图旁显示DOM返回值（不再是单独的"actual"字段）

## 五、老大可能没想到的测试点（清单体 - 待讨论）

### ① 数据完整性维度（10个点）
1. **跨系统一致性**：图纸库数据与供应商模块/价格模块的同步（同一物料编码）
2. **大文件性能**：上传50MB/100MB PDF的耗时和成功率
3. **特殊字符文件名**：中文/空格/特殊符号/超长文件名
4. **批量操作极限**：一次性勾选500/1000条数据
5. **并发用户**：3人同时上传/归档同一图纸
6. **时区/夏令时**：有效期跨时区计算是否正确
7. **历史数据迁移**：旧系统数据导入后字段映射
8. **版本回滚**：归档→恢复→归档，状态机是否回到初始
9. **删除硬删除vs软删除**：删除按钮是真的删还是标记删除
10. **审计日志完整性**：每一步操作是否都有操作记录

### ② 安全维度（7个点）
11. **越权访问**：普通用户访问 `/system/moduleconfiguration/drawConfig`
12. **SQL注入**：文件名/搜索框输入 `' OR 1=1--`
13. **XSS攻击**：文件名包含 `<script>alert(1)</script>`
14. **CSRF**：跨站请求伪造防护
15. **Token过期**：ACCESS_TOKEN过期后操作是否被拦截
16. **文件类型伪造**：.pdf扩展名实际是.exe
17. **路径穿越**：文件名包含 `../../etc/passwd`

### ③ 性能维度（6个点）
18. **首页加载时间**：3G网络下首屏时间
19. **大数据量分页**：100万行数据的分页性能
20. **搜索响应时间**：10万条数据下的搜索耗时
21. **并发上传**：100用户同时上传
22. **长会话稳定性**：连续运行24小时内存泄漏
23. **缓存命中率**：相同查询的二次响应时间

### ④ 兼容性维度（5个点）
24. **多浏览器**：Chrome/Edge/Firefox/Safari/360
25. **多分辨率**：1920x1080/1366x768/移动端
26. **多操作系统**：Windows/Mac/Linux客户端
27. **IE兼容**：如果客户有要求
28. **打印导出**：PDF打印是否完整

### ⑤ 业务规则维度（8个点）
29. **有效期计算规则**：过期30天前的图纸
30. **必填字段联动**：有效期必填开启时，关闭是否真的必填
31. **审批工作流**：上传是否需要审批
32. **多语言**：中英文切换（如果支持）
33. **通知机制**：临期/过期通知是否真的发送
34. **导入导出**：批量导入Excel的字段映射
35. **二维码/RFID关联**：物理资产和数字图纸绑定
36. **离线/弱网**：断网后重连的数据一致性

### ⑥ 可用性维度（4个点）
37. **空状态**：列表为0条时的提示文案和按钮可用性
38. **错误提示**：网络错误/服务错误的具体提示
39. **帮助文档**：页面是否有帮助链接/操作指南
40. **快捷键**：搜索/刷新/提交的快捷键支持

### ⑦ 数据分析维度（3个点）
41. **统计准确性**：临期/过期/有效三个数字加起来是否=总数
42. **历史趋势**：30天内每天的上传/归档/恢复数量
43. **用户行为分析**：最常被归档的物料TOP10
