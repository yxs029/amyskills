# 全量测试报告规范（V2样式）

全量报告是**决策导向的仪表盘**，给老板/项目经理做发布决策用。

## 核心样式：V2深色渐变

- body背景：`linear-gradient(135deg, #0f2027 0%, #203a43 50%, #2c5364 100%)`
- 卡片：`background:#fff` + `border-radius:12px` + `box-shadow`
- 顶部Hero进度条：绿→红渐变（通过率比例）

## 9个区块（必须全部包含）

### 1. Hero
- 标题：`{系统名} 全量自动化测试报告 v{版本}`
- 副标题：`{模块数} 模块 · {用例数} 用例 · 全自动化执行 · {引擎}`
- 元信息条（5个胶囊）：日期/URL/账号/工具/截图数
- 门禁判定大胶囊（右上角）

### 2. KPI仪表盘（6列）
| 卡片 | 顶边颜色 | 内容 |
|------|----------|------|
| 总用例 | #1890ff | 数 + 备注 |
| 通过 | #52c41a | 数 + 通过率% |
| 失败 | #f5222d | 数 + 失败率% |
| 跳过 | #faad14 | 数 + 跳过率% |
| 通过率 | #722ed1 | % + 门禁要求 |
| P0通过率 | #cf1322 | % + 通/总数 + 要求 |

### 3. 发布门禁Banner
- 红色渐变背景（#cf1322 → #820014）
- 🚫 大图标
- 标题：`发布门禁判定：通过/不通过`
- 原因（▸ 列出）：
  - P0通过率
  - P0缺陷数
  - 阻断模块列表

### 4. 双栏：模块表 + 严重度饼图

**左：模块表（占比 1.2fr）**
| # | 模块 | 用例 | P0 | 通过率 | 判定 |
|---|------|------|----|---------|------|
- 通过率列：彩色进度条 + 百分比
- 判定列：彩色标签
- 模块名：跳转链接（`../HTML报告/{模块名}_测试报告.html`）

**右：严重度饼图（占比 1fr）**
- SVG donut chart
- 中心显示缺陷总数
- 4段：P0红/P1橙/P2黄/INFO蓝
- 图例在下方

### 5. 模块详情卡

每模块一张卡：
```
┌──────────────────────────────────────────────┐
│ [01] 模块名  [❌ 不通过]  [📊 查看详细报告 →]   │
├──────────────────────────────────────────────┤
│ 用例: X | 通过: X | 失败: X | 跳过: X | X% | ⏰ 时间 │
├──────────────────────────────────────────────┤
│ 🎯 核心发现：[核心问题]                       │
└──────────────────────────────────────────────┘
```

颜色规范：
- 卡片边框：pass绿 / fail红 / warn橙
- finding块：左边框颜色对应状态

### 6. P0关键缺陷聚焦
- 标题：`🚨 P0 关键缺陷聚焦（X 个 · 必须修复）`
- 卡片网格：auto-fill, minmax(420px, 1fr)
- 卡片：`{用例ID} | {严重度P0}` + 描述 + 实际结果 + 模块名

### 7. P1高优缺陷
- 同P0结构，但标签颜色为橙

### 8. P2/INFO其他缺陷
- 标题：`📝 P2/INFO 其他缺陷（X 个）`
- 标签颜色为蓝或灰

### 9. 修复建议
- rec卡片列表
- urgent红 / high橙 / normal黄（顶部4px彩色边）
- 每张rec：标题 + `<ul>` 列表

## 文件位置

**主输出**：`交付层/全量报告/{系统名}_全量测试报告_v{版本}_{日期}.html`

**与子模块报告的关系**：
- 同一目录结构：`交付层/` 下分 `HTML报告/`（子模块）和 `全量报告/`（汇总）
- 全量报告用相对路径跳转：`../HTML报告/{模块名}_测试报告.html`

## 哪些信息需要从子模块报告自动提取

✅ 必须自动提取（不要手写）：
- 模块统计（用例数/通过数/失败数）
- 缺陷数据（5种格式 + 智能去重）
- 通过率/P0通过率

❌ 可以手工编排（可读性 > 准确性）：
- Hero副标题文案
- 核心发现描述（finding）
- 时间戳
- 修复建议（rec）
