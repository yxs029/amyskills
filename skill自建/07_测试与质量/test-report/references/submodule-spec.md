# 子模块测试报告规范

子模块报告是**测试的完整证据链**，给测试人员/开发定位问题时用。

## 7个区块（必须全部包含）

### 1. 标题区
- 系统名（测试系统的全称）
- 模块名（本次测试的具体模块）
- 执行时间（开始-结束时间）
- 测试URL
- 测试账号
- 测试人/工具

### 2. 4列统计卡片
```
[总用例 (蓝)] [通过 (绿)] [失败 (红)] [跳过 (黄)]
```
颜色规范：
- 总用例：#1890ff
- 通过：#52c41a
- 失败：#ff4d4f
- 跳过：#faad14

### 3. 3列优先级统计
```
[P0 紧急 (红)] [P1 高优 (橙)] [P2 一般 (蓝)]
```
每列显示：`已通过/总数 + 通过率%`

### 4. 通过率进度条
- ≥80%：绿色（#52c41a）
- 50-79%：橙色（#faad14）
- <50%：红色（#ff4d4f）

### 5. 用例详情（核心区块）

每个用例一张卡片，必须包含：

```
┌──────────────────────────────────────────────┐
│ [用例ID]  标题     [P0/P1/P2]  [通过/失败]    │
├──────────────────────────────────────────────┤
│ 前置条件: xxx（可选）                           │
│ 实际结果: xxx                                  │
│ ⚠️ 缺陷框（仅失败用例）                        │
│   - 严重度: P1                                │
│   - 描述: 重置按钮未生效                       │
│   - 预期 vs 实际:                              │
│     预期: 全部清空                              │
│     实际: 搜索框值=[质量]                       │
│   - 复现路径: 1.点击重置 2.观察状态...         │
│ 执行步骤:                                      │
│   步骤1  动作 → 结果（绿色左边框=通过）         │
│   步骤2  动作 → 结果（红色左边框=失败）         │
│ 截图: 灯箱画廊（base64内嵌）                    │
└──────────────────────────────────────────────┘
```

### 6. 缺陷汇总表
表格列：`# | 严重度 | 描述 | 实际结果`
- 与失败用例一一对应
- 失败用例必须在汇总表中

### 7. 测试总结
- 总通过率
- 各优先级通过率
- 缺陷数（分P0/P1/P2）
- 测试结论：
  - **通过**：P0 100%且 P1 ≥ 90%且无P0/P1缺陷
  - **有条件通过**：P0 100%但 P1 < 90%或存在P2缺陷
  - **不通过**：P0未100%或存在P0/P1缺陷

## 技术要求

1. **单文件交付**：HTML+CSS+JS全内联
2. **截图base64内嵌**：不依赖外部图片
3. **灯箱交互**：点击缩略图放大，ESC关闭
4. **响应式**：max-width 1200px，画廊 auto-fill 200px
5. **文件命名**：`{模块名}_测试报告.html`
6. **存放目录**：`交付层/HTML报告/`，同步到 `report/enhanced/`

## 错误反例（不要这样做）

❌ 只给 PASS/FAIL 表格，没有步骤和截图 → 人类无法判断测试是否到位
❌ 截图只放文件链接不内嵌 → 打开报告看不到图
❌ 失败用例没有缺陷框 → 无法追溯问题
❌ 没有优先级统计 → 无法判断核心用例覆盖情况
