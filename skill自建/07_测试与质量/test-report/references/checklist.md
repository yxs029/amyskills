# 输出前必检项

## 子模块报告 checklist

打开报告前，先在终端跑：
```bash
# 验证HTML无未替换的{{变量}}
grep -o '{{[A-Z_]\\+}}' 文件.html | sort -u
# 应该输出空（无残留变量）
```

### 视觉检查
- [ ] 标题/副标题/账号等元信息正确显示
- [ ] 4个统计卡片数字加起来 = 总用例数
- [ ] 进度条颜色对应通过率（绿/橙/红）
- [ ] 至少1个用例有步骤展示（验证步骤区样式正确）
- [ ] 至少1个失败用例有 defect-box
- [ ] 截图能显示（灯箱点击能放大）
- [ ] 缺陷汇总表行数 = 失败用例数

### 数据准确性
- [ ] `stats.total = len(cases)`
- [ ] `stats.pass + stats.fail + stats.skip = stats.total`
- [ ] `priorities.p0.pass + priorities.p1.pass + priorities.p2.pass = stats.pass`（按优先级）
- [ ] 缺陷列表的严重度分布合理

### 假阳性检测（用户强制要求 - 2026-07-18）
- [ ] 审计每个用例的 steps 数量：steps<=1 的"PASS"用例是**假阳性**，不可信
- [ ] 审计截图数量：screenshots==0 的用例不可信
- [ ] 如果浅测试比例 > 30%，报告中必须标注"含假阳性，建议重跑深度步骤版"
- [ ] 深度步骤版标准：每用例3-6步，每步有截图+DOM断言返回值
- [ ] 详见 `monitored-test-framework` skill 第十一-B节"深度步骤测试规范"

### 输出文件
- [ ] HTML可独立打开（不依赖外部资源）
- [ ] 截图目录同步到 `交付层/HTML报告/测试截图/`
- [ ] 镜像副本同步到 `report/enhanced/`

## 全量报告 checklist

```bash
# 检查跳转链接是否指向存在的文件
grep -o 'href="../HTML报告/[^"]*\.html"' 文件.html | sort -u | while read href; do
  file=$(echo $href | sed 's/href="..\///' | tr -d '"')
  test -f "交付层/$file" || echo "❌ $file 不存在"
done
```

### 数据正确性
- [ ] 6个KPI数字与子模块聚合一致
- [ ] P0缺陷数 = sum(子模块报告中所有P0)
- [ ] 模块表的 pass+fail+skip = 总用例数
- [ ] 门禁Banner文案与KPI数据一致

### 视觉检查
- [ ] 深色背景 + 白色卡片（V2样式）
- [ ] 顶部渐变进度条颜色渐变自然
- [ ] 6个KPI卡片顶边彩色条颜色正确（蓝/绿/红/黄/紫/红）
- [ ] 门禁Banner整条红色
- [ ] 双栏布局（左表右图）在≥1024px宽度时生效
- [ ] 至少1个模块详情卡能展开finding
- [ ] P0/P1/P2缺陷卡颜色规范：
  - P0：左边框#cf1322红
  - P1：左边框#fa8c16橙
  - P2/INFO：左边框#1890ff蓝
- [ ] 严重度饼图扇形颜色对应图例

### 跳转链接
- [ ] 12个有独立报告的模块名都能点击跳转
- [ ] 2个无独立报告的模块显示"详见V2"或"-"
- [ ] 相对路径正确（`../HTML报告/{名}_测试报告.html`）

### 文件
- [ ] 输出到 `交付层/全量报告/{系统名}_全量测试报告_v{版本}_{日期}.html`
- [ ] HTML可独立打开
