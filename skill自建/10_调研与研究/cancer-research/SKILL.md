# Cancer Research Skill（方案索引 + 药物库 双轨版）

> **🚨 全局安全边界**：本 skill 产出的报告/数据库**仅供与主治医生讨论参考**，
> 不构成治疗建议。所有用药/方案必须在执业医师指导下进行。

## 核心设计哲学

**为什么从"全量报告"切换到"方案索引 + 药物库"**：
1. **报告是给人快速判断用的**——患者/家属/医生每周关心的是"这周有什么新方案
   能用、谁做的、去哪找"。药物组成/剂量是处方细节，不该挤占阅读注意力
2. **药物是物料清单（BOM）性质**——会反复被多个方案引用，独立成库避免重复
3. **中西医放一个库**——同一种药/方剂可能中西医都用（如黄芪），统一管理 +
   tag 区分，避免重复维护

**关键资产**：
- **方案索引报告**（Markdown，按周产出）：每周新增 1 篇
- **药物物料清单库**（SQLite）：持续累积，可按方案/癌种/中西医 tag 查询
- **两套资产通过 `report_id` 关联**——一份方案报告引用若干药物记录

## Inputs to collect

从调用方(cron prompt 或用户消息)的入参中提取/确认以下变量。

| 参数 | 类型 | 说明 | 示例 |
|------|------|------|------|
| `cancer_type` | 必填,中文 | 癌种中文名 | `直肠癌`、`肺癌`、`肝癌` |
| `stage` | 必填,中文 | 分期范围 | `晚期(IV期)`、`早期(I-II期)`、`中期(III期)`、`全分期` |
| `medicine_type` | 必填,枚举 | 分册 | `western` / `tcm` / `combined` |
| `output_dir` | 可选 | 报告输出目录 | 默认 `C:\Users\AaronMY\.mavis\workspace` |
| `db_path` | 可选 | SQLite 库路径 | 默认 `<output_dir>\drugs.db` |
| `biji_sync` | 可选,布尔 | 是否同步报告到 Get笔记 | 默认 `true` |
| `cron_name` | 可选 | 触发本轮的 cron 名 | `cancer-tcm-weekly` |
| `mode` | 可选 | `incremental`(默认,周更) / `full`(完整重建) | `incremental` |

**分册命名映射**（保持兼容历史）：
- `western` → `西医` / 文件名后缀 `西医`（如 `直肠癌晚期西医_方案索引_2026-08-27.md`）
- `tcm` → `中医` / 文件名后缀 `中医`
- `combined` → `合集`

## Output contract

每次执行产出 **2 套资产 + 1 个同步动作**：

**文件**：`{cancer_type}{stage}{分册名}_方案索引_{YYYY-MM-DD}.md`
**位置**：`{output_dir}/`（同目录带日期后缀）
**长度**：**严格 3000-5000 字**（用户确认的精简版）
**结构**（3 大块 + 1 段结语）：

```markdown
# {癌种}{stage}{分册名} 方案索引（{YYYY-MM-DD}）

> **更新时间**：{YYYY-MM-DD}
> **核心问题**：本周/本期有哪些新方案？这些方案在哪能做？谁在做？
> **本报告不含药物配方/剂量**——药物细节见 drugs.db（按方案 ID 查询）
```

### 资产 2：药物物料清单库（SQLite）
**文件**：`{output_dir}/drugs.db`（首次自动创建 schema）
**位置**：用户主目录 workspace
**Schema**（详见 `references/drugs-schema.md`）：
- `drugs` 表：药物主数据（drug_id, name_cn, name_en, name_pinyin, category, 
  medicine_type_tag, mechanism, indications, evidence_level, source_doi, 
  last_updated）
- `regimens` 表：方案（regimen_id = 方案 ID, name, cancer_type, stage, 
  medicine_type, summary, source_doi, last_updated）
- `regimen_drugs` 表：方案-药物关联（regimen_id, drug_id, role, dose_default, 
  notes）
- `regimen_hospitals` 表：方案-医院关联（regimen_id, hospital, department, 
  lead_team, contact, location, notes）

**中西医 tag 设计**：
- `medicine_type_tag` 字段：`western` / `tcm` / `both`
  - `western` — 西医专用（化疗药/靶向药/PD-1 等）
  - `tcm` — 中医专用（方剂/中成药/中药材）
  - `both` — 跨体系共用（如黄芪既可健脾中医方剂，又可作西医辅助营养支持）
- **同一种药可出现在多个方案中**——通过 `regimen_drugs` 多对多关联
- **同一家医院可对应多个方案**——通过 `regimen_hospitals` 多对多关联

- 同步对象：**只同步方案索引报告**（不直接同步药物库——库文件是结构化资产，
  通过查询接口访问）
- 标题：`{癌种}{stage}{分册}方案索引({YYYY-MM-DD})`
- 标签：癌种 / 分册 / 日期（API 限 ≤4 个标签）
- 知识库：`生活家庭父母`（topic_id=`yYvwkO80`）

## Procedure（按顺序执行）

### 1. 解析入参 + 初始化环境（~1 分钟）

1. 从 prompt 提取 `cancer_type` / `stage` / `medicine_type` / `mode` / `cron_name`
2. **初始化 SQLite 库**（如不存在）：
   ```bash
   sqlite3 {db_path} < references/drugs-schema.sql
   ```
3. 读取最近 2-3 篇方案索引报告（保持风格一致）

### 2. 检索本周进展（~5-10 分钟，核心工作量）

按分册检索：
- **西医**：CSCO/NCCN/ESMO/ASCO、Lancet/JCO/NEJM、ESMO GI 摘要、ClinicalTrials.gov、
  卫健委公告、复旦肿瘤/中山六院/中国医科院肿瘤公开发布
- **中医**：Gut Microbes/中国中西医结合杂志、中医药管理局公告、西苑/广安门/龙华
  公开发布、中医肿瘤专家共识、相关 RCT

每个新进展**只关注**：
- 方案名（regimen）
- 适用人群（分期/分子分型）
- 能干什么（临床获益）
- 关键数据（mPFS/mOS/ORR/HR/P 值）
- 证据来源（DOI/链接）
- 主理团队/医院
- 联系方式（官网/公众号/挂号渠道）

**不需要关注**（外置到 SQLite）：
- 药物组成 / 剂量 / 煎服法 / 联合方案
- RCT 详细方法学 / 不良反应分级
- 药理机制 / 网络药理学靶点

### 2. 检索本周进展（~5-10 分钟，核心工作量）

按分册检索：
- **西医**：CSCO/NCCN/ESMO/ASCO、Lancet/JCO/NEJM、ESMO GI 摘要、ClinicalTrials.gov、
  卫健委公告、复旦肿瘤/中山六院/中国医科院肿瘤公开发布
- **中医**：Gut Microbes/中国中西医结合杂志、中医药管理局公告、西苑/广安门/龙华
  公开发布、中医肿瘤专家共识、相关 RCT

每个新进展**只关注**：
- 方案名（regimen）
- 适用人群（分期/分子分型）
- 能干什么（临床获益）
- 关键数据（mPFS/mOS/ORR/HR/P 值）
- 证据来源（DOI/链接）
- 主理团队/医院
- 联系方式（官网/公众号/挂号渠道）

**不需要关注**（外置到 SQLite）：
- 药物组成 / 剂量 / 煎服法 / 联合方案
- RCT 详细方法学 / 不良反应分级
- 药理机制 / 网络药理学靶点

### 2.5 可信度验证（质量门控，~3 分钟）

> **核心原则：不是搜到了就加，而是验证过了才加。**

每条新方案/新医院入库前，必须做可信度评估，结果写入
`credibility_score` 和 `credibility_notes` 字段。

#### 方案可信度评级

| 等级 | 标准 | 处理方式 |
|------|------|---------|
| **A（高）** | 官网可访问 + **至少 2 个独立来源**一致提到（期刊+医院官网/权威媒体） + 有临床数据（RCT/III 期）或患者评价 | ✅ 正常入库，报告中标记 A |
| **B（中）** | 有权威单源（期刊论文/官方公告/三甲医院官网），但缺少多源交叉验证或大样本 RCT | ✅ 入库，报告中标记 B，备注"待进一步验证" |
| **C（低）** | 网站打不开 / 仅有单一非权威来源（自媒体/营销号）/ 无患者评价 / 信息存疑 | ⚠️ 入库但标记 C，报告中以灰色显示并注明"可信度低，建议核实" |

#### 医院可信度评级

| 等级 | 标准 |
|------|------|
| **A（高）** | 官网可访问（link_status=ok）+ 三甲/国家重点专科/旗舰医院 + 有明确科室和专家信息 |
| **B（中）** | 官网可访问或有权威来源但 link_status 非 ok（403/521 反爬）+ 医院真实存在；或 link_status=ok 但非重点专科 |
| **C（低）** | 官网无法访问 + 非三甲/民营机构 / 信息存疑 |

#### 验证操作步骤

1. **链接验证**：用 `scripts/verify_links.py` 检查医院官网是否可访问（已有自动化）
2. **交叉验证**：对每个新方案，至少找 2 个独立来源确认：
   - 来源 1：原始论文/会议摘要/官方公告
   - 来源 2：医院官网/权威媒体（人民网/新华网/医脉通/梅斯医学）的报道
   - 如果只找到 1 个来源 → 最高评 B
3. **患者评价**（可选但加分）：在好大夫在线/觅健/知乎等平台搜索该方案/医院的患者反馈
4. **记录验证过程**：在 `credibility_notes` 里写明"来源 X 个 / 交叉验证情况 / 患者评价有无"

**重要**：C 级方案/医院**不丢弃**，而是标记后入库——让用户自己判断，
但必须在报告中明确标注，不能假装和 A 级一样可靠。

### 3. 写入方案索引报告（3000-5000 字）

按模板填充 3 大块（**严格控制字数**）：

| 章节 | 目标字数 | 写法 |
|------|---------|------|
| 一、本期新增/更新方案 | 1500-2500 | 表格为主，5-10 行；每行 80-150 字 |
| 二、方案→医院映射 | 800-1200 | 表格，5-10 行 |
| 三、官方/科普/患者社区渠道 | 500-800 | 分层 bullet 列表 |
| 四、关键提示 | 100-200 | 3-5 行 |

**判断标准**：报告长度 = 方案数 × 200-300 字 + 渠道部分 800 字。**不要**展开
药物机制、辨证分型、方剂煎服法等细节——这些都在 SQLite 库。

### 4. 同步增量到 SQLite 库

用 Python 脚本（`scripts/sync_drugs.py`）执行：
1. 插入新方案（regimens 表）
2. 插入/更新药物（drugs 表；按 name_pinyin 去重）
3. 关联方案-药物（regimen_drugs 表）
4. 关联方案-医院（regimen_hospitals 表）

**首次初始化**：把历史 50+ 个药物（从 2026-08-20 版主报告迁移）一次性灌入。
**之后每周**：只灌本周新方案涉及的药物。

### 5. 备份与追加日志

- 方案索引报告**不**做版本备份（每篇带日期，是天然版本）——除非是 `mode=full`
- 更新日志追加：`{output_dir}/{癌种}调研-更新日志.md` 末尾追加一条
- 同步的 Get笔记 note_id 写进日志

### 6. Get 笔记同步（若 `biji_sync=true`）

加载 getnote skill，把方案索引报告保存为新笔记。
- 标题：`{癌种}{stage}{分册}方案索引({YYYY-MM-DD})`
- 内容：报告全文
- 标签：`{癌种简}` / `{分册}` / `{YYYY-MM-DD}` / `方案索引`（API 限 ≤4 标签）
- 知识库：`生活家庭父母`（topic_id=`yYvwkO80`）
- **不**同步 drugs.db（库文件是结构化资产，本地查询）

记录 note_id，写进日志和汇报。

### 7. 汇报

- 1 句"周更完成"
- 3-5 条"本周最值得关注的新方案"（带方案 ID）
- 报告文件路径 + note_id
- drugs.db 本周新增药物数 / 累计药物数
- 不在汇报中复述药物细节——引导用户去 drugs.db 查

## Failure handling

| 失败场景 | 处理方式 |
|---------|---------|
| 入参缺失/冲突 | 停止，问用户 |
| drugs.db 损坏 | 从 `references/drugs-schema.sql` 重建（**会丢数据**——提示用户） |
| 检索结果稀少 | 照常生成，"本期新增方案"段标"本周无重大新方案" |
| web_search 全失败 | 只基于上版小幅更新；本周进展条数可缩到 3-5 条 |
| Get笔记 API 失败 | 报告已落盘，记 log，汇报"未同步到笔记" |
| Python sqlite3 不可用 | 切换到手动 SQL（用户提供 sqlite3 CLI） |

## 与旧版（2026-08-20 前）主报告的关系

- **2026-08-20 版主报告作为"内容快照基线"**——药物组成/剂量/辨证分型/方剂
  等历史细节**仍然可查**（如果用户需要，回到 `直肠癌晚期中医治疗方案调研报告.md`
  历史版本即可）
- **新流程产出的方案索引报告是"目录+索引"**——只指引"去哪找、找谁、要什么"
- **历史所有方案细节迁移到 drugs.db**——首次初始化时一次性灌入
- **定期归档**（建议季度）：把 13 周方案索引汇编成"季度方案目录"——便于回顾
