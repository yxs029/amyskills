# 硬核知识分享类文章排版

## 概述

本技能定义了硬核知识分享类文章的标准 Markdown 排版格式，基于《营销管理》读书分享系列真实发布文章提炼而成。使用时，复制 `templates/article_template.md` 作为起点，将占位符替换为实际内容即可。

## 整体结构（五段式框架）

文章采用「总-分-总」逻辑，固定包含以下五个模块：

| 编号 | 模块定位 | 核心任务 |
| :--- | :--- | :--- |
| 开场白 + 痛点故事 | 无编号，纯文本 | 自我介绍 + 真实场景引入，让读者产生代入感 |
| `### #01` | 提出核心问题 | 点明普遍痛点，引出本文核心概念（加粗术语） |
| `### #02` | 案例应用（HOW） | 通过具体案例展示概念如何落地，按维度分块 |
| `### #03` | 理论解析（WHAT） | 给出正式定义，用表格结构化拆解模型要素 |
| `### #04` | 个人经验 + 泛化 | 作者亲身经历 + 将概念延伸至更广泛场景 |
| `### #05` | 总结升华 | 提炼本质，引用金句，以反问/行动号召收尾 |

各模块之间使用 `---` 水平分割线隔开。

## Markdown 语法规范

### 标题层级

| 层级 | 语法 | 说明 |
| :--- | :--- | :--- |
| 模块标题（唯一级别） | `### #01 标题文字` | 三级标题；带数字编号；**不使用颜色标签** |
| 正文内小标题（维度名） | `**维度名称**` | 加粗，独占一行，非标题级别 |

> 本格式**仅使用一个标题级别**（`###`），不嵌套 `####`。维度名、指标名等次级内容均用 `**加粗**` 处理，保持排版的极简性。

### 文本强调

加粗（`**文本**`）有三种用途，需严格区分：

| 用途 | 示例 |
| :--- | :--- |
| 核心痛点/问题 | `**数据越来越多，但越看越迷糊**` |
| 专业术语/概念名称 | `**营销仪表板（Marketing Dashboard）**` |
| 关键结论/金句 | `**让每一分营销预算都有迹可循，让每一个决策都有据可依**` |

### 段落与间距

- **句号即换行（核心铁律）**：每行只写一句话，句号（`。`）后立即换行，绝不在同一行内连写两句。经统计，原文档中单句行占比达 **88%+**，是最严格执行的排版规则。
- 行与行之间空一行（即两个回车），形成视觉分组。
- 逻辑转折处或模块末尾使用含两个空格的空行（`  `）增加视觉留白，控制阅读节奏。
- **例外情形**：冒号引导句（`科特勒提出了一个解决方案：`）、引号内对话句、列举项（如指标名称）等本身不以句号结尾的行，不受此规则约束。

### 表格的使用

表格**仅用于 `#03 理论解析` 模块**，对模型的构成要素进行结构化拆解。标准格式为三列：`要素名称 | 核心问题 | 详细说明`，要素名称加粗。

```markdown
| 模型要素 | 核心问题 | 说明 |
|---|---|---|
| **短期结果维度** | 营业额和股东价值是否达标？ | 关注当期财务表现，反映营销投入的即时回报 |
| **品牌资产维度** | 顾客认知、态度与行为是否健康？ | 关注品牌长期价值，包括认知度、忠诚度等 |
```

### 分割线

每个主要模块（`#01` ~ `#05`）之间，以及开场白与第一个模块之间，统一使用 `---` 分割。

## 注意事项

- **句号即换行**：每行只写一句话，句号后立即换行，这是最需要主动执行的排版习惯。
- **不使用** `#`（一级）和 `##`（二级）标题，文章标题在文档外部（如公众号标题栏）处理。
- 模块编号从 `#01` 开始，总结固定为 `#05`。
- **不使用** `<font color="">` 等 HTML 颜色标签，保持纯 Markdown 风格。
- 案例主角建议使用虚构的品牌/人物（如“夜猫咖啡”），便于灵活演绎。
- `#04` 个人经验模块必须包含作者视角的真实感，避免写成纯理论延伸。
- 全文加粗次数控制在 **8-12 处**，过多会稀释强调效果。
- 保留用户给你的原始内容，不要修改任何内容
