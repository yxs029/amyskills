## 常见错误及避免

| 错误 | 后果 | 避免方法 |
|------|------|----------|
| 一次性读多个文件 | 上下文爆炸，理解碎片化 | 一次只读一个 |
| 边读边输出笔记 | 思考不深入，输出质量差 | 读完再汇报，汇报完再输出 |
| 跳过雪松指示直接输出 | 可能浪费精力在不重要的内容上 | 每步等确认 |
| 表格过多 | 雪松不喜欢看表格 | 用纯文本+缩进代替 |
| 自己编内容 | 脱离原文，引入错误 | 严格从原文提炼，不自由发挥 |
| 混淆两种输出时机 | 提前写完整一页纸造成浪费 | 分清楚"子系列中间报告"和"全部学完后的完整输出" |
| 子系列完成后直接输出完整笔记 | 浪费大量时间做雪松不需要的事 | 进阶系列中间用"轻量级学习报告"汇报，等雪松说"继续"再学下一个 |
| 大文件进度不汇报 | 雪松不知道读到哪里了 | 长文件（>200段）每50段主动发进度条 |
| 用delegate_task做批量输出 | 子代理遇到API 429限流，导致任务失败 | 批量输出文件时，直接用execute_code批量写，不要委托子代理 |
| delegate_task任务数超限 | 超过max_concurrent_children会报错 | 每批最多3个任务，书多时分批调用 |
| 遇到API超时导致子代理max_iterations失败 | 书太大时token消耗高，初次读取就超时 | 重试该任务，或直接手动写方法论（书的核心框架是已知的） |
| 遇到.docx直接read_file | 返回空内容 | 必须用terminal调python-docx读取 |
- 遇到.docx文件名中有冒号`：`或全角符号时，terminal的`python-docx`会报`PackageNotFoundError`，此时可能是文件名编码问题或实际文件名不同（如"研黑客"vs"调研黑客"）。先用`ls`确认实际文件名再读取。

**雪松的格式偏好（硬性规则）**：
- 方法论、案例库、学习感悟，优先用**清单体/段落文字**，避免使用表格
- 如果必须用列表，用**纯文本缩进列表**（如 `1. 要点一：说明`），不用 Markdown 表格
- 汇报时优先用自然段落，不要用列表，除非雪松明确要求"给我列个表"
- 雪松说"清单体笔记发我"时，意思是把方法论/案例内容转成**段落化的清单格式**（每个要点单独成段），而不是表格
