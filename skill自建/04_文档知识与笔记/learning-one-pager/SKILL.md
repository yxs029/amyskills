# 通用理论学习Skill（一页纸学习法）

## 触发条件

当雪松要求学习任何理论知识、教程、课程、文章时自动触发：
- "学习这个课程" / "帮我梳理这个教程" / "读一下这篇文章"
- 一堂课程、得到课、PDF教程、公众号文章、技术文档、书籍章节等
- 任何理论性、框架性、方法论性质的内容

## 核心原则

**一个一个学，不要一次性全部学完，否则上下文会爆掉。**

每个文件独立学习，学完一个汇报一个，等雪松确认后再学下一个。

**系列课分节机制**：
如果课程分成多个独立文件（如24节气系列、系列课连载），每个独立文件视为一个子系列，按以下节奏推进：
- 学完一个子系列 → 轻量级汇报 → 等雪松说"继续"
- 学完一组（每6个子系列） → 发出汇总包 → 等雪松确认
- 全部学完 → 整理完整输出文件

**汇总包触发时机**：每学完6个子系列（如春夏一组：立春/雨水/惊蛰/春分/清明/谷雨），立即发出汇总包，不要等到全部学完才汇总。

## 通用学习SOP（适用所有内容类型）

### 第一步：识别内容类型

内容分为两类，处理方式不同：

**A. 讲座转写型**（如课程录音转写）
- 特点：口语化、有案例、有故事、有讲师风格
- 方法：提炼框架 + 提取金句 + 整理案例

**B. 框架方法论型**（如PPT课件、说明书、学术文章）
- 特点：结构化、术语多、有步骤和清单
- 方法：提取核心模型 + 找到使用场景 + 配套清单

### 第二步：确定来源

优先从本地文件学习（效率更高）：
- 本地文件：`~/.hermes/memory/` 目录下
- IMA知识库：用ima skill读取

如果文件不存在或需要更新，再从源获取。

### 第三步：阅读并提炼（每200行三段式汇报）

每次只读一个文件，边读边提炼：
- 核心定义是什么（方法论 = 操作定义）
- 核心框架是什么（几个关键要素）
- 典型错误/误区是什么
- 使用场景是什么（什么时候用、什么时候不用）
- 最有感觉的一句话

**读取规范**：
- 用`read_file`而非terminal里的`cat`
- 大文件（>200行）需要分offset读取
- 每读完200行，输出三段式汇报：

```markdown
## 进度汇报（第N段 / 共M段）

### 本段核心内容
- [内容要点1]
- [内容要点2]

### 我的学习感悟
[阿元对这段内容的理解和消化]

### 引导思考
这段内容让我想到几个问题：
1. 这段内容和你自己有什么关系？
2. 你最近有没有类似的经历或感受？
3. 这个方法论可以用在你哪个场景？
```

**引导问题的三类设计**（每次必用，不要换其他问题）：
- **关系连接**：这段内容和你自己有什么关系？
- **经验连接**：你最近有没有类似的经历或感受？
- **应用连接**：这个方法论可以用在你哪个场景？

**重要例外**：如果雪松明确说"给我摘要，等我下一步指令"，则按他要求的节奏读——读一小段就停下来汇报，不要擅自连续读多个200行。

**边读边在脑子里提炼核心框架，不要急着输出。**

### 第四步：学习完后汇报（轻量级）

用简洁格式汇报，**不要**附带大量列表或详细格式：

```
## [文件名] 学习报告

### 这节课讲了什么
（1-3句话概括）

### 核心框架
（提炼的结构化框架）

### 雪松的故事主线（如果是故事型）
阶段 | 核心卡点 | 解法

### 最有感觉的一句话
> "引述"

---
汇报完毕。等你指示。
```

**重要：不要在汇报时创建文件、不要整理一页纸、不要做完整输出。** 只做口头汇报，等雪松说"继续"或等整个系列学完再创建文件。

### 第五步：等雪松指示

雪松说"继续"再继续，或等雪松指定下一个文件。

雪松说"可以了，整理输出"时，才创建完整的输出文件。

## 5步法工作流（雪松指定，2026-05-28更新）

1. **分系列** — 把整个课程按节气分成系列课（每个节气 = 一个系列）
2. **建目录** — 在课程目录下创建「阿元学习笔记」目录
3. **建子目录** — 每个系列学完后，在阿元学习笔记下创建 `[节气-主题]` 子目录
4. **写方法论** — 每个系列提炼一个方法论，存为 `00方法论-[课程主题]-[自增后缀].md`
5. **写案例库** — 每个系列收集案例，存为 `10案例库-[课程主题]-[自增后缀].md`
6. **加Obsidian双向链接** — 方法论末尾加「相关案例」，案例库开头加「本案例支撑的方法论」，每个条款和案例之间交叉引用

**命名规则：**
- 子目录：`[节气名]-[主题/子主题]` 格式，如 `立春-目标管理`
- 方法论文件：`00方法论-[课程主题]-[自增后缀].md`，前缀00 = 方法论
- 案例库文件：`10案例库-[课程主题]-[自增后缀].md`，前缀10 = 案例库
- 前缀预留：20=（预留其他类型，如复盘模板/练习工具等）

**完成后报告格式（每学完一个子系列必须发送）**：
```markdown
## 📋 【XX系列】完成报告

### ✅ 方法论文件
**路径：** ...
**核心方法论概要：**
- 方法论1：（1句话）
- 方法论2：（1句话）

### ✅ 案例库文件
**路径：** ...
**收录案例：**
- 案例1：标题
- 案例2：标题

### 📁 本系列目录结构
```
阿元学习笔记/
└── XX-YY/
    ├── 00方法论-XX主题-序号.md
    └── 10案例库-XX主题-序号.md
```

**进度：X/16 系列**
下一系列：【XXX系列】
```

## Obsidian双向链接格式（雪松指定，2026-05-28）

**目的**：方法和案例做关联，支持Obsidian知识库图谱查询。

**格式要求**：

**方法论文件末尾**加「相关案例」链接：
```markdown
## 相关案例

全部案例请参阅：[[10案例库-芒种效能法则-01]]
```

**每个方法论条款下方**加「相关案例」引用：
```markdown
> **相关案例**：[[10案例库-芒种效能法则-01#案例2：小叶的最小正反馈闭环]]
```

**案例库文件开头**加「本案例支撑的方法论」引用：
```markdown
> **本案例支撑的方法论**：[[00方法论-芒种效能法则-01]]
```

**每个案例末尾**加「支撑方法论」引用：
```markdown
> 支撑方法论：[[00方法论-芒种效能法则-01#方法论4：最小正反馈闭环]]
```

**语法**：`[[文件名#章节锚点]]` — 文件名是另一个md文件，#后面是目标章节的标题（Obsidian会自动渲染为可点击链接）。

**Obsidian中查看**：双向链接会在图谱视图（graph view）中显示为节点和连线，方便追踪方法和案例之间的关联。

- 用"核心问题"来定义每个方法论的边界
