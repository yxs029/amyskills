# 文章排版风格提炼与发布 Checklist

## 一、整体排版风格概述

综合 5 篇样本文章来看，这一组文章属于典型的**微信公众号知识分享型长文**，核心风格可以概括为：**强钩子开场、短段落推进、编号化分节、案例先行、模型提炼、个人实践收束**。文章不是以学术论文的严密章节为主，而是以移动端阅读体验为中心，通过连续短段、分隔线、图片、表格、加粗金句和个人叙事，帮助读者在较低阅读压力下理解一个商业模型或品牌案例。

这一风格的关键不只是“排版好看”，而是让文章形成稳定的阅读路径：先用一个现实痛点或具体商业事件抓住注意力，再通过案例展开冲突，然后引入《营销管理》中的理论模型，接着回到个人实践或当代商业场景，最后用总结金句完成记忆锚定。

## 二、5 篇样本的共同排版特征

| 维度 | 共同特征 | 样本中的典型表现 |
| --- | --- | --- |
| 开场方式 | 先抛出具体场景、痛点或冲突，而不是直接讲理论 | 调研文章从“闭门造车”“问卷失真”开场；迪士尼文章从家庭游玩成本开场；可口可乐文章从历史节点开场 |
| 作者定位 | 开头或前言部分嵌入作者自我介绍和栏目定位 | “阅读商业经典，探索个人品牌”“我是爱搭知识库的软件测试工程师，你可以叫我艾伦” |
| 章节结构 | 主体统一使用 `### #01` 形式编号分节 | 多数文章使用 `#01` 至 `#05/#07/#08` 推进内容 |
| 分隔方式 | 大章节之间使用 `---` 横线分隔 | 每个主章节前后基本都有横线，移动端视觉边界清晰 |
| 段落节奏 | 短段落、高留白，一段通常 1—2 句 | 大量独立短句、判断句和转折句，便于手机端扫读 |
| 理论呈现 | 先讲案例，再抽象为模型或概念 | “怎么用”在前，“是什么”在后，避免一上来就讲定义 |
| 案例组合 | 常用“大公司案例 + 小店案例 + 我的尝试”三段式 | 美国航空、夜猫咖啡、作者自己的 AI 测试系统实践 |
| 强调方式 | 用加粗突出核心概念、关键判断和文章金句 | `**营销调研不是为了证明你是对的，而是为了发现你哪里错了**` |
| 视觉素材 | 每个关键章节附近插入图片，承担停顿和补充说明作用 | 文章中多次使用 `![Image](...)`，通常位于章节开头、案例后或总结前 |
| 表格使用 | 理论模型或对比关系用表格承载 | 调研过程五步骤、调研手段五方法、定位要素与迪士尼案例对照 |
| 收束方式 | 最后一节通常为“总结升华”，以金句结束 | “用观察代替臆想，用实验代替争论……” |
| 附录处理 | 资料来源或参考链接放在最后，避免干扰正文主线 | 迪士尼文章使用引用块形式设置参考资料附录 |

## 三、文章类型与结构规则

这组文章主要有两类结构：一类是**营销模型拆解文**，另一类是**品牌案例复盘文**。两类文章共享排版语言，但章节功能略有差异。

| 类型 | 适用主题 | 推荐结构 | 代表样本 |
| --- | --- | --- | --- |
| 营销模型拆解文 | 调研过程模型、调研手段、定位模型、营销框架 | 痛点开场 → 模型解决什么问题 → 怎么用 → 模型是什么 → 我的尝试 → 总结升华 | 调研过程模型、调研手段、迪士尼定位 |
| 品牌案例复盘文 | 历史商业事件、品牌资产案例、营销灾难复盘 | 历史节点/事件开场 → 事件回顾 → 冲突升级 → 反转结果 → 核心概念 → 核心教训 → 延伸思考 → 附录 | 可口可乐新可乐事件 |

对于后续写作，建议不要机械固定章节数量，而应固定**章节任务**。也就是说，文章可以是 5 节，也可以是 7 节，但必须完成“引入冲突、展开案例、解释模型、连接实践、总结升华”这几个关键动作。

## 四、标题与小标题规则

样本标题通常具有强烈的内容承诺感，不只是说明主题，还会告诉读者“为什么要读”。标题常见结构是：**编号或日期 + 理论来源/案例对象 + 冲突问题 + 结果收益**。

| 标题层级 | 排版规则 | 推荐写法 | 示例 |
| --- | --- | --- | --- |
| 文章主标题 | 使用一级标题 `#`，标题中可以包含日期、系列编号或模型来源，标题中不得使用冒号（改逗号） | `# 【编号】《营销管理》之模型名，痛点问题，收益承诺` | `# 【0924】《营销管理》之调研过程模型，这套 5 步调研法，帮你省下百万试错成本` |
| 案例型标题 | 使用"案例对象 + 重新定义/冲突 + 方法论意义"，标题中不得使用冒号和破折号 | `# 案例对象，从 A 到 B，模型视角下的重新定位` | `# 1-3 迪士尼，从大众乐园到"游乐园行业爱马仕"，迪士尼的重新定位` |
| 历史型标题 | 使用"日期 + 历史上的今天 + 事件冲突"，标题中不得使用冒号 | `# 【日期】历史上的今天，事件名 + 冲突表达` | `# 【2026-06-10】历史上的今天，可口可乐的「营销灾难」新可乐的79天生死劫` |
| 主章节标题 | 使用三级标题 `### #01`，编号与标题之间保留空格，标题中不得使用冒号 | `### #01 章节主题，一句话说明本节任务` | `### #02 怎么用调研过程模型？` |
| 子章节标题 | 在案例组或理论细分中使用四级标题 `####`，标题中不得使用冒号 | `#### 案例对象的做法` 或 `#### **概念名（English）**` | `#### 美国航空公司的组合拳` |
| 理论小标题 | 使用加粗词组，不必每个点都升为标题；加粗小标题中的冒号也改逗号 | `**第一步，方法名（作用）**` | `**第一步，焦点小组法（找方向）**` |

需要注意的是，早期可口可乐版本使用了红色编号格式 `<font color="#ff0000">#01</font>`，但后续 4 篇样本更多采用纯 Markdown 的 `### #01`。如果目标是公众号编辑器兼容性和迁移便利，建议以**纯 Markdown 编号标题**作为默认规则；如果需要更强视觉栏目感，再使用红色编号作为增强样式。

## 五、正文排版规则

正文排版的核心是让读者在手机屏幕上持续读下去。因此，样本文章普遍避免长段落，转而使用短段落、独立句、留白和关键句加粗来制造节奏。

| 模块 | 排版规则 | 示例或说明 |
| --- | --- | --- |
| 开场段 | 用 3—6 个短段落连续制造场景和冲突 | 每段只讲一个动作或一个心理反应，形成连续镜头感 |
| 关键判断 | 单独成段，并尽量加粗 | `**用错误的方法去收集数据，把客户口是心非的答案当成了真理**` |
| 段落长度 | 一段通常控制在 1—2 句，不建议超过 4 行 | 适合公众号移动端阅读 |
| 留白 | 段落之间保留空行，图片和表格前后也保留空行 | 避免正文压迫感 |
| 转折句 | “但……”“这就出现了一个问题”“真正重要的是……”可单独成段 | 用来推动阅读节奏和逻辑转向 |
| 口语化解释 | 理论术语后必须接大白话解释 | `这句话翻译成大白话就是……` |
| 类比句 | 用生活类比解释抽象概念 | 妈妈织的毛衣、游乐园行业爱马仕、情绪账单等 |
| 金句 | 文章结尾或章节结尾使用一句高度凝练的加粗句 | `**定位决定比较对象，品牌决定溢价上限。但是，边界必须拿捏得当！**` |

## 六、图片、表格与列表规则

样本文章不是纯文字长文，而是有明显的图文节奏。图片的作用不是装饰，而是作为章节停顿、案例证据、模型图示或情绪缓冲。表格则主要用于把复杂模型压缩成可扫读的结构。

| 元素 | 使用规则 | 推荐位置 | 注意事项 |
| --- | --- | --- | --- |
| 图片 | 每 1—2 个主章节至少出现 1 张图片 | 章节开头、案例结束后、理论表格前后、总结前 | 图片前后保留空行，不要让图片紧贴正文 |
| 表格 | 用于模型要素、方法对比、案例映射 | “是什么”“有哪些”“如何对应案例”部分 | 表格列数建议 2—3 列，避免手机端横向过宽 |
| 编号列表 | 用于流程步骤、操作步骤、案例执行顺序 | “怎么用”部分 | 每个编号后使用加粗小标题，下面接解释段 |
| 无序列表 | 用于罗列痛点、版本、对比项 | 不宜过多，避免文章变成提纲 | 每个项目尽量短，不承载复杂论证 |
| 引用块 | 用于资料说明、风险提示、附录参考资料 | 文章开头或结尾 | 不建议在正文中频繁使用，避免打断阅读 |

### 8.1 维度·案例·实践·建议·总结格式专项检查

> 当文章按 `SKILL.md` 中的"章节格式模板与约束"组织结构（包含维度分析 / 案例 / 实践 / 建议 / 总结章节）时，额外检查以下项。不使用该模板的文章这些项标"不适用"。

| 类别 | 检查项 | 是否完成 |
| --- | --- | --- |
| 主章节编号 | 维度 / 案例 / 实践 / 建议 / 总结章节是否仍使用 `### #0x` 编号，与子标题风格保持一致？ | ☐ |
| 维度无标签 | 维度小标题是否不出现"维度 1、维度 2、维度"等任何标签字，标题直接是 `#### <分类名>，xxx` 形式（冒号已改逗号）？ | ☐ |
| 维度加粗 | 维度逗号后的相关文字是否用 `**...**` 加粗，并单独成行？ | ☐ |

### 8.2 标点换行专项评分（硬规则）

> 标点换行是 2026-08 新增的硬规则。以下检查项**不设"不适用"**，所有文章必须 100% 通过。任一项未通过，总分直接扣 10 分（从满足率中扣除），且必须返工修复后才能交付。

| 序号 | 检查项 | 检查方法 | 分值 | 是否通过 |
| ---: | --- | --- | ---: | :---: |
| P1 | 正文中每个句号 `。` 后都有换行（空行分隔） | 正则搜索 `。[^\n|]` 匹配表格外正文，结果为 0 | 2 | ☐ |
| P2 | 正文中每个问号 `？` 后都有换行 | 正则搜索 `？[^\n|]` 匹配表格外正文，结果为 0 | 2 | ☐ |
| P3 | 正文中每个冒号 `：` 后都有换行 | 正则搜索 `：[^\n|]` 匹配表格外正文，结果为 0 | 2 | ☐ |
| P4 | 正文中每个分号 `；` 后都有换行 | 正则搜索 `；[^\n|]` 匹配表格外正文，结果为 0 | 1 | ☐ |
| P5 | 正文中每个感叹号 `！` 后都有换行 | 正则搜索 `！[^\n|]` 匹配表格外正文，结果为 0 | 1 | ☐ |
| P6 | 所有标题（`#`/`##`/`###`/`####`）中无冒号 `：` | 正则搜索 `#{1,4}\s.*：`，结果为 0 | 1 | ☐ |
| P7 | 正文无中文破折号 `——` | 正则搜索 `——`，结果为 0 | 1 | ☐ |
| | **合计** | | **10** | |

**评分规则**：
- 7 项全部通过 → 标点专项满分 10/10，计入总满足率
- 每失败 1 项 → 扣对应分值，从总分中扣除
- P1-P3（句号/问号/冒号）任一失败 → 不允许交付，必须返工
- P4-P7 失败 → 返工修复后交付

**自检命令（Python，推荐）**：

```python
# -*- coding: utf-8 -*-
import re, sys
sys.stdout.reconfigure(encoding='utf-8')

file_path = r'你的文件路径.md'  # ← 改这里
with open(file_path, 'r', encoding='utf-8') as f:
    lines = f.read().split('\n')

# 闭合引号/括号（标点后可以紧跟这些字符不算违规）
closing = '\u201d\u300f"\u2019\uff09\u3011\u300d\\]*'
punct = '\u3002\uff1f\uff01\uff1b\uff1a'
bad_pattern = re.compile('[' + punct + '][' + closing + ']*[^\\s' + closing + ']')
bold_re = re.compile(r'\*\*[^*]+\*\*')
heading_re = re.compile(r'^(>+\s*)?(#{1,4}\s)')
list_re = re.compile(r'^\s*[-*]\s|^\s*\d+[.)]\s')

has_fm = len(lines) > 0 and lines[0].strip() == '---'
in_fm, fm_count, violations = False, 0, []

for ln, line in enumerate(lines, 1):
    s = line.strip()
    if has_fm and s == '---' and fm_count < 2:
        fm_count += 1; in_fm = (fm_count == 1); continue
    if in_fm or s == '' or s == '---' or line.startswith('|'): continue
    if heading_re.match(line):
        if '\uff1a' in line: violations.append(f'L{ln} [P6标题冒号] {s[:70]}')
        continue
    if line.startswith('>') or list_re.match(line):
        if '\u2014\u2014' in line: violations.append(f'L{ln} [P7破折号] {s[:70]}')
        continue
    if bad_pattern.search(bold_re.sub('', line)):
        violations.append(f'L{ln} [标点未换行] {s[:70]}')
    if '\u2014\u2014' in line: violations.append(f'L{ln} [P7破折号] {s[:70]}')

if violations:
    print(f'未通过，共 {len(violations)} 处：')
    for v in violations: print(f'  {v}')
else:
    print('标点换行检查全部通过（P1-P7）')
```

**自检命令（PowerShell）**：

```powershell
# 读取排版后文件（排除表格行和 frontmatter）
$lines = Get-Content $filePath -Encoding UTF8
$body = $lines | Where-Object { $_ -notmatch '^\|' -and $_ -ne '---' -and $_.Trim() -ne '' }

# 正则含义：标点后允许跟若干闭合引号/括号（含中文弯引号“”‘’），若之后还有非空白正文 = 违规
$pattern = '[。？！；：][""''”’）】」』〕]*[^\s""''”’）】」』〕]'

$bad = @()
foreach ($line in $body) {
    if ($line -match '^#{1,4}\s') {
        if ($line -match '：') { $bad += "[P6标题冒号] $line" }
        continue
    }
    $stripped = $line -replace '\*\*[^*]+\*\*', ''
    if ($stripped -match $pattern) {
        $bad += "[标点未换行] $line"
    }
    if ($line -match '——') {
        $bad += "[P7破折号] $line"
    }
}

if ($bad.Count -gt 0) {
    Write-Host "标点换行检查未通过，共 $($bad.Count) 处：" -ForegroundColor Red
    $bad | ForEach-Object { Write-Host "  $_" -ForegroundColor Red }
} else {
    Write-Host "标点换行检查全部通过（P1-P7）" -ForegroundColor Green
}
```

- `（截图占位）` 独占行
