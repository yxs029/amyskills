# Article Layout Formatter

## Inputs to collect

从用户输入提取以下信息；缺失则按默认推断（不要为风格细节反复追问用户）：

- 原文（Markdown 或纯文本）
- 文章类型（营销模型拆解 / 品牌案例复盘 / 混合型）—— 缺失则从正文判断
- 标题、栏目署名、读者人设 —— 缺失则按通用公众号风格

## Procedure

### 1. 接收并判断文章类型

读取用户给定的文章，按以下分类判断：

| 类型 | 判断标准 | 推荐结构 |
| --- | --- | --- |
| 营销模型拆解文 | 核心是解释某个模型、方法、框架或工具 | 痛点开场 → 模型解决什么问题 → 怎么用 → 模型是什么 → 我的尝试 → 总结升华 |
| 品牌案例复盘文 | 核心是复盘某个品牌、历史事件或商业案例 | 历史/事件开场 → 事件回顾 → 冲突升级 → 反转/结果 → 核心概念 → 核心教训 → 延伸思考 → 附录 |
| 混合型 | 既有大案例，也有模型拆解和个人实践 | 以案例为主线，嵌入模型解释，再落到个人实践或现代应用 |

如果用户没有明确标题，根据正文生成一个（主题 + 冲突 + 收益三要素）。

### 2. 重构文章骨架

将原文改造成 Markdown 结构。默认格式：

```markdown
# 文章标题

开场场景。

继续补充痛点或冲突。

其实，你可能忽略了一个关键问题：

**一句话点破问题本质。**

---

### #01 章节标题

正文。

（截图占位）

---

### #02 章节标题

正文。
```

> 标题格式：主章节用 `### #01`（纯井号 + 空格 + 编号），**不要带反斜杠**。参考样本早期版本使用 `### \#01`，新写作时统一为 `### #01`。

排版硬性规则：

| 项目 | 规则 | 为什么 |
| --- | --- | --- |
| 主标题 | 一级标题 `#` | 公众号编辑器默认识别为大标题 |
| 主章节 | `### #01`、`### #02` 连续编号 | 移动端节奏清晰、便于定位 |
| 分隔线 | 大章节之间用 `---` | 手机端视觉边界、避免大段堆叠 |
| 段落 | 每句独占一段，遇标点即换行（见下方"标点换行规则"） | 移动端扫读友好、降低 AI 检测率 |
| 加粗 | 核心概念、关键判断、结尾金句 | 视觉锚点 + 金句传播力 |
| 截图占位 | 章节开头后、案例后、表格前后、总结前 | 留给用户补图、节奏控制 |
| 表格 | 模型/方法/维度/案例映射优先表格 | 压缩复杂信息 |
| 结尾 | "总结升华"章节 + 加粗金句 | 记忆锚定 + 利于转发 |
| 编号格式 | 统一阿拉伯数字 `01/02/03`，禁止混用 `01`、`1`、`一、` | 视觉一致 |

#### 标点换行规则（硬规则，不可豁免）

正文中遇到以下标点，**必须在标点后换行**（空行分隔成独立段落）：

| 标点 | 规则 | 示例 |
| --- | --- | --- |
| 句号 `。` | 句号后必须换行 | `这是第一句。` ↵ 空行 ↵ `这是第二句。` |
| 问号 `？` | 问号后必须换行（含反问句） | `你真的想清楚了吗？` ↵ 空行 ↵ |
| 冒号 `：` | 正文冒号后必须换行 | `他说了一件事：` ↵ 空行 ↵ `具体内容是……` |
| 分号 `；` | 分号后必须换行 | `第一个原因；` ↵ 空行 ↵ `第二个原因；` |
| 感叹号 `！` | 感叹号后必须换行 | `太惊人了！` ↵ 空行 ↵ |

**标题中的冒号**：所有标题（`#`/`##`/`###`/`####`）中不得出现冒号 `：`，一律改为逗号 `，`。原因：冒号标题是 AIGC 检测的高权重特征。

| 错误 | 正确 |
| --- | --- |
| `### #01 对手的城墙：可能正在风化` | `### #01 对手的城墙，可能正在风化` |
| `#### 维度名：解释` | `#### 维度名，解释` |
| `# 标题：副标题` | `# 标题，副标题` |

**例外（不执行标点换行）**：
- 表格单元格内的标点（表格是结构化数据，不拆行）
- YAML frontmatter（`---` 包裹的元数据）
- 加粗标记内部的标点（`**这是一句话。**` 整体作为一段，句号在 `**` 内不拆，但段末标点后的换行规则仍然适用）
- 引用块 `>` 内的标点（保持引用完整性）
- `（截图占位）` 独占一行，不拆

**自检方法**：排版完成后，用以下方式检查正文（排除表格和 frontmatter）：

**快速搜索**（在编辑器中逐一搜索，排除加粗块内的标点）：
- 搜索 `。` —— 每个句号都应在行末（或紧跟闭合引号 `"` 后在行末）
- 搜索 `？` —— 每个问号都应在行末（同上）
- 搜索 `：` —— 每个正文冒号后都应换行
- 搜索 `；` —— 每个分号后都应换行
- 搜索 `#{1,4} .*：` —— 标题中含冒号 = 违规

**精确自检**：使用 `references/layout_checklist.md` 中 8.2 节提供的 Python 或 PowerShell 脚本（自动排除加粗块、表格、闭合引号，零误报）。

### 3. 插入截图占位

每篇至少 3 处截图占位；长文每 1—2 个主章节一处。

格式必须单独成行：

```markdown
（截图占位）
```

> 禁止把"（截图占位）"写在段落中间（"前面（截图占位）后面"是错误格式），会被编辑器当成普通字符。

优先插入位置：

| 位置 | 目的 |
| --- | --- |
| 开场冲突之后 | 第一处视觉停顿 |
| 核心案例之后 | 承接案例截图、新闻截图、商业场景图 |
| 理论模型表格前后 | 模型图、流程图、思维导图 |
| 实践之后 | 工具截图、笔记截图、操作过程 |
| 总结升华之前 | 结尾前的视觉缓冲 |

### 4. 执行 checklist 评分

根据 `references/layout_checklist.md` 的"更新后的发布前 Checklist"逐项评分：

1. 逐项判断每条 checklist 是否满足。
2. "不适用"项从分母剔除（不可滥用：只有文章类型天然不涉及的项才能标"不适用"）。
3. 计算满足率：`满足率 = 已满足项数 / 适用项总数 × 100%`。
4. **满足率必须 ≥ 95%**。

> 95% 阈值的理由：35+ 项 checklist 中，文章类型不同会让部分项天然不适用（"是否嵌入作者身份"对纯案例文可能不适用）。从分母剔除后，**剩余项要求 100% 命中**——适用项不允许失败。

高权重项必须满足：

- 结构：完成"冲突引入—案例展开—理论提炼—实践应用—总结升华"
- 编号：主章节统一 `### #编号`，编号连续，**不带反斜杠**
- 节奏：短段落、高留白、关键句单独成段
- **标点换行：句号/问号/冒号/分号/感叹号后必须换行；标题冒号改逗号（硬规则，不达标直接扣 10 分）**
- 截图：合理的"（截图占位）"
- 理论：专业概念有大白话解释
- 视觉：表格、编号列表、加粗金句使用得当
- 收束：结尾有总结升华和加粗金句

### 5. 循环修订直到达标

如果满足率 < 95%，按以下顺序修订：

1. 补结构缺口（开场 / 案例 / 理论 / 实践 / 总结）
2. 修排版格式（标题层级、编号、横线、占位、表格）
3. 修阅读节奏（拆长段、加留白、关键句独立成段）
4. 修强调方式（补必要加粗、删过度加粗）
5. 重新评分

最多 3 轮完整修订。第 3 轮仍未达 95%：在最终说明中列出未达标项、原因、需用户补充的内容；只要排版层面能修复就继续修。

### 6. 输出文件

交付一个 `.md` 文件，只放排版后的文章正文，不放评分表（除非用户要求）。

**命名建议**：`排版_v<版本号>_<原文件名主标题>.md`

> 命名规则：把"备注 + 版本号"从后缀移到前缀。`<版本号>` 取自原文件名的 V 编号（如 V3.3、V3、v1）；若原文无版本号则默认 v1。`<原文件名主标题>` = 日期 + 主标题 + 分类标签（如"三维度校准版"），**去掉原文的"-日期-来自【xxx】"溯源信息**。
> 例：`7月31日  专利壁垒——爱迪生与好莱坞（三维度校准版）V3.3（公众号排版版）-2026年07月27日-来自【得到大脑】` → `排版_v3.3_7月31日  专利壁垒——爱迪生与好莱坞（三维度校准版）.md`

交付消息简要说明：

- 已按文章排版制作 workflow 完成
- checklist 满足率（多少 %）
- 已插入"（截图占位）"几处
- 附上最终 Markdown 文件

## 章节格式模板与约束

按以下统一模板整理章节结构（适用于"商业模型拆解 / 品牌案例复盘 / 混合型"全文）：

> **与 section 1 的关系**：section 1 给的"营销模型拆解文 / 品牌案例复盘文 / 混合型"推荐结构，是本模板里"子标题"部分的填充顺序指引；本模板的"维度 / 案例 / 实践 / 建议 / 总结"是统一的横切骨架。两套不冲突，section 1 决定子标题里写什么、新模板决定整篇文章用什么骨架。
>
> **实践段是可选的**：如果作者的"我的尝试"内容已经嵌入到 建议 段里（参考 `reference_ibook_breaker_effect.md` 的写法），可以省略独立的"### 实践"段，直接从"### 案例"过渡到"### 建议"。

```markdown
### #01 <子标题1>
……

### #0n <子标题n>

### #0n+1 <维度分析章节>
#### <分类名>，xxx
#### <分类名>，xxx
……
#### <分类名>，xxx

### #0n+2 <案例相关章节>
<案例1>
<案例2>
……
<案例n>

### #0n+2.5 <实践相关章节>
<实践1>
<实践2>
……
<实践n>

### #0n+3 <建议相关章节>
#### <建议1>
#### <建议2>
……
#### <建议n>

### #0n+4 <总结章节>
<总结>
<金句>
<思考题>
```

###约束条件

**主章节**：统一使用 `### #0x` 编号（含子标题、维度分析、案例、实践、建议、总结），与本 skill 默认章节编号规则一致。

**维度**：标题形式为 `#### <分类名>，xxx`，不带"维度 1、维度 2、维度"等任何标签字；逗号后的相关文字用 `**...**` 加粗，并单独成行。

**案例**：**不可出现**"案例 1、案例 2"这类编号，也**不可出现**"案例"这个标签字；正文仅以 `**<内容>**` 整段加粗、单独成行呈现。

**实践**：**不可出现**"实践 1、实践 2"这类编号，也**不可出现**"实践""我的尝试""个人实践"等标签字；正文仅以 `**<内容>**` 整段加粗、单独成行呈现。

**建议**：`#### <建议N>` 标题中**不出现**"建议 1、建议 2"这类编号，也**不出现**"建议"字样；标题文本直接用建议内容本身。

**金句 / 思考题 / 总结**：**不可出现**"金句""思考题""总结"这类标签字；各自以 `**<内容>**` 单独成行加粗呈现。

**加粗方式**：维度内容、案例、实践、建议、金句、思考题、总结一律使用 `**...**` 包裹。

**段行**：每个加粗段落必须**单独成行**，且段落前后留空行。

### 关键原则

1. **只整理格式，不修改原文内容** —— 排版时严禁改动原文措辞、句序；标点换行（句号/问号/冒号/分号后换行）、破折号替换为逗号、标题冒号改逗号属于格式调整，不属于内容修改
2. **维度无标签** —— "维度"小标题不出现"维度 1、维度 2、维度"等任何标签字，标题直接是 `#### <分类名>，xxx`，与"建议""案例""实践"等其他元素保持完全一致的无标签风格
3. **其余元素去除标签** —— 案例、实践、建议、金句、思考题、总结在最终输出中**不得出现**任何对应的编号或"案例 / 实践 / 我的尝试 / 个人实践 / 建议 / 金句 / 思考题 / 总结"等标签字
4. **加粗且独占一行** —— 所有需要强调的内容用 `**...**` 加粗，并单独成行
5. **保持 #01 编号** —— 所有 ### 级主章节（子标题、维度、案例、实践、建议、总结）统一使用 `### #0x` 编号，与本 skill 默认章节编号规则一致

### 输出示例

**错误**（出现标签字、没加粗、没单独成行、标题用冒号）：

```markdown
#### 建议 1：重视用户反馈
建议 2：建立数据看板
**金句**：认知决定边界。
```

**正确**（无标签字、内容加粗独立成行、标题用逗号）：

```markdown
#### 重视用户反馈

#### 建立数据看板

**认知决定边界。**
```

## Output contract

每次执行必须交付：

- **一个 `.md` 文件**（手机端可复制到公众号编辑器继续配图）：命名 `排版_v<版本号>_<原文件名主标题>.md`（备注+版本号放前缀，去掉原文"-日期-来自【xxx】"溯源信息）
- **满足率 ≥ 95%**（适用项 100% 命中）
- **至少 3 处"（截图占位）"**（每 1—2 个主章节一处）
- **格式约束**：章节编号 `### #01`（无反斜杠）、横线 `---`、加粗金句结尾、表格 2—3 列
- **新模板格式约束**：按"章节格式模板与约束"排版时,需满足 — 加粗段落独立成行、维度不带"维度 N""维度"等任何标签字、案例/实践/建议/金句/思考题/总结**不出现对应标签字**、实践段以加粗段落呈现
- **不交付**：评分表、过程稿、PDF（除非用户明确要求）

## Failure handling

- **素材不足**（原文 < 300 字且用户不补充）→ 暂停修订，报告"原文信息密度不足，无法达到 95%，请补充 X 主题的素材"；不硬凑
- **3 轮修订仍未达标** → 交付当前最优版本 + 评分表 + 未达标项清单 + 下一步建议
- **用户原文带图片** → 提醒：本 skill 专做"无图初稿"，已有图片的精排请走 `image-layout` 类工作流（本 skill 暂不覆盖）
- **用户要求"不加占位符"或"不要评分"** → 接受用户的显式偏好，但交付时标注"未走标准 checklist 评分"

## 正文标点规范

### 1. 标点换行（硬规则）

正文中遇到句号 `。`、问号 `？`、冒号 `：`、分号 `；`、感叹号 `！`，必须在标点后换行（空行分隔）。详见上方"标点换行规则"表格。

### 2. 破折号替换

正文中不得使用中文破折号（——）。将所有用于解释、转折、追加说明的破折号均替换为逗号（，）。

例如：

- 错误：他给柜台取了个名字——京东多媒体。
- 正确：他给柜台取了个名字，京东多媒体。

### 3. 标题冒号改逗号

所有标题中不得出现冒号 `：`，一律改为逗号 `，`。冒号标题是 AIGC 检测的高权重特征。

- 错误：`### #01 对手的城墙：可能正在风化`
- 正确：`### #01 对手的城墙，可能正在风化`

- 表格单元格内的标点
- YAML frontmatter
- 引用块 `>` 内的标点
- `（截图占位）` 独占行
