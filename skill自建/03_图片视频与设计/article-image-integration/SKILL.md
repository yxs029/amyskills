## Procedure

### 1. 读取文章 + 判断入口

读取原文后扫描两种状态，决定走哪个分支：

- **入口 A：文章无占位符** → 默认每个主章节配 1 张图
- **入口 B：文章有占位符（如 `(截图占位)`）** → 仅为有占位符的章节配图

提取每章节的：

- 核心主题（1 句话总结）
- 关键人物/场景/物品（如"夜猫咖啡"、"调研团队"等）
- 情感基调（困惑、对比、启发、总结等）
- 上下文里已有的视觉元素（避免与正文描述重复）

### 2. 输出风格建议表（核心交付物）

按 **"先提案再量产"** 原则，在生成任何图片前**先列风格建议表与用户确认**。表格字段：

| 字段 | 含义 | 限制 |
| --- | --- | --- |
| 序号 | 1, 2, 3... | 按章节顺序 |
| 章节 | `#01 模型介绍` 这样的标识 | 不含正文 |
| 占位描述 | 这张图要传达什么 | **≤ 50 字** |
| 功能分类 | 见下方 5 类 | "画什么"维度（信息图/场景图/框架图/情感图/数据图） |
| 视觉风格包 | 来自 13 类参考图库 | "长什么样"维度（如 `02_现代深色信息图`、`07_奇幻魔幻写实`） |
| 风格要点 | 1-2 句具体描述 | 引用视觉风格包的特征词（深色/暖金/等距/...） |

**功能分类**（5 类，按章节内容选，不要超出）：

#### 2.5.1 智能匹配（默认流程）

按 **"决策树优先 → 子目录深挖 → 兜底"** 三层：

```
第 1 层：决策树粗筛
  └─ 读 `references/AI图片分类/README.md` 的"选图决策树"
  └─ 按章节调性（如"科技/增长"→01 或 02）粗筛 1-2 个候选风格包
  └─ 命中 → 进入第 2 层

第 2 层：子目录精筛
  └─ 读候选子目录的 README.md（如 02_现代深色信息图/README.md）
  └─ 列出子目录里所有图片文件名 + 子 README 的"适合配图的主题"段落
  └─ 按章节占位描述选 1-2 张最贴合的具体参考图
  └─ 选中 → 记下图片绝对路径，进入步骤 4（批量生成）

第 3 层：兜底（仅在 1-2 层都选不出来时触发）
  └─ 用 06_现代生活化插画（最通用的视觉风格包）
  └─ 子目录里的任意 1-2 张图作为参考
```

**关键规则**：

- **决策树命中就不要再读子 README 的"适合主题"段落**，除非子目录里图片很多需要二次筛选
- **跨分类混搭是允许的**——一篇文章的不同章节可以选不同视觉风格包，由章节调性决定
- **同视觉风格包 + 不同章节**也可以混用——比如 #01 和 #02 都用 02_现代深色信息图，但选不同的参考图，体现"同风格 + 不同场景"

### 3. 批量生成所有图片

参考图确认后，调用 `image_synthesize` 工具直接批量生成（**v3 简化**：不再出样张等用户确认，参考图本身就是精准的视觉锚点）：

- 工具的 `requests` 数组单次最多 10 张；超过则分批调用
- **每张图必须喂入参考图**（`input_file_paths` 至少 1 张，参考图匹配表里选定的）：
  - **路径必须用 2.5.2 步骤复制到 `<workspace>/_ref_imgs/` 的副本，不是 skill 库原始路径**
  - 章节选用了同视觉风格包 → 喂 2.5.2 步骤复制好的 workspace 副本（同风格包任意一张即可）
  - 章节选了不同视觉风格包 → 喂对应风格包的 workspace 副本
  - **同 batch 内的多张图可以共用同一组参考图**（节省 input_file_paths 配额）
- 每张图 prompt 必须包含：
  - **场景描述**：与章节内容直接对应的具体场景
  - **视觉隐喻**：用图形化方式呈现抽象概念（如"差距"用鸿沟表示）
  - **色彩情绪**：与章节情感基调匹配（问题章节冷色调，解决方案暖色调）
  - **风格锚点（v2 升级）**：写明「参考附件 `<workspace>/_ref_imgs/<简短文件名>.webp` 的视觉风格：[参考图关键视觉特征]」，**路径使用 2.5.2 步骤复制好的 workspace 副本**

- **参考图匹配表 + 参考图展示**（v2 新增，v3 强化为"质量关口"）：风格表确认后、批量生成前完成；包括表格输出 → 参考图从 skill 库复制到 `<workspace>/_ref_imgs/` → `<deliver-assets>` 展示 → 用户确认
- **图片文件夹**：`配图版_v<版本号>_<产物名>_images/chapter{NN}.png`，16:9，PNG
- **带图 Markdown**：`配图版_v<版本号>_<产物名>.md`（图片相对路径 `配图版_v<版本号>_<产物名>_images/...`）

## Failure handling

- **文章 < 500 字** → 暂停，提示"原文信息密度不足，无法给出有意义的章节分析和配图建议，请补充内容或先排版"
- **章节没有明确主题**（如纯过渡段）→ 合并到相邻章节，或在风格表里标"跳过该章节"，由用户决定
- **产物名（slug）无法推断**（无 frontmatter title、用户未提供）→ 暂停，提示用户给一个产物名（如"解绑红利"、"硅谷分手"等）
- **产物名含非法字符**（Windows 文件名不允许 `\/:*?"<>|`）→ 暂停，提示用户用合法字符
- **YYYYMMDD 子目录创建失败**（权限/磁盘满）→ 暂停，提示用户检查 workspace 写入权限；不绕过此步骤
- **参考图库读取失败**（路径不存在 / 权限问题）→ 暂停，提示用户检查 `<skill_root>/references/AI图片分类/` 路径是否完整；如果 skill 整体迁移过、参考图丢失，提示用户重新放置完整图库（13 个子目录）到该位置；不要绕过此步骤硬画（v2 流程的核心价值就是参考图锚定）
- **决策树全部不命中**（罕见）→ 自动用 06_现代生活化插画兜底，告知用户"匹配不到精确风格，已用通用兜底"
- **图片生成失败**（某章节）→ 重试 1 次；仍失败则该章节标"配图失败-已跳过"，继续后续章节；最终报告里列失败清单
- **用户中途修改风格表 / 参考图** → 走"修改 → 重新展示参考图 → 用户再确认"流程，**不需要重新出样张**（v3 简化）
- **用户中途换风格包**（比如从 02 换到 04）→ 必须重做"参考图匹配表"对应行
- **文章已带图**（无需再配） → 提醒用户"已带 X 张图，无需再生成"，询问是否仍要补充缺失章节的图
- **用户要求"全章节都出图但文章只有 1 个章节"** → 提示"文章只有 1 个主章节，建议补充分节或接受 1 张图"
- **临时缓存 `_ref_imgs/` 清理失败**（步骤 6.1）→ 提示用户手动删除 `<workspace>/_ref_imgs/`；不阻塞交付
- **2.5.2 展示参考图失败**（参考图复制到 workspace 失败 / `<media>` 标签不渲染 / 路径在 workspace 之外）→ 改用 `<media type="file" src="..." caption="..." />` 以文件形式交付，或先把参考图复制到 `<workspace>/_ref_imgs/` 再重试；**这是质量关口，不要跳过**（v3 已无样张环节，参考图成为唯一确认机会）
