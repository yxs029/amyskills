# 故障排查与替代路径

遇到错误码、用户无 API key、或需要平台限制对照时读本文。

## 错误码对照

### TikHub

| 状态 | 含义 | 处理 |
|------|------|------|
| `HTTP 401` `"API token is missing"` | 未带鉴权头 | 检查 `Authorization: Bearer <key>` |
| `HTTP 402` `"requires payment and does not accept free credit"` | **微信系路由拒绝免费额度** | 必须充值，见下文 |
| `HTTP 405` `"Method Not Allowed"` | 用了 GET | 微信系接口需 **POST** |
| `HTTP 200` `"will incur a charge"` | 成功并计费 | 正常 |

诊断 402 时的关键动作：**用同一把 key 请求一个非微信接口**（如 `douyin/web/fetch_user_post_videos`）。若该请求返回 200，则证明 key、鉴权格式、调用方式均正确，402 纯粹源于微信系路由的独立计费策略，而非配置错误。这一步能避免把计费问题误判为代码问题。

查询余额：

```bash
curl -s -H "Authorization: Bearer $TIKHUB_API_KEY" \
  "https://api.tikhub.io/api/v1/tikhub/user/get_user_info"
```

关注 `user_data.balance`（付费余额）与 `user_data.free_credit`（免费额度）。微信系只认前者。

### JustOneAPI（备选服务）

| code | 含义 |
|------|------|
| `0` | 成功 |
| `100` | token 无效或未激活 |
| `301` | 采集失败，可重试 |
| `302` / `303` | 触发频率限制 / 日配额耗尽 |
| `601` | 共享账户余额不足 |
| `602` | 当前 token 累计预算上限 |

两步调用：`get-video-basic-info/v1`（传 `feedInfo`，接受分享链接）取 `objectId`，再用 `get-video-download-url/v1` 取下载地址。超时建议设 120 秒，微信服务端响应慢。

## 解密失败排查顺序

按此顺序检查，命中率从高到低：

1. **key 与 url 是否来自同一次响应。** 最常见原因。每次请求返回新配对，混用必失败。
2. **`decode_key` 是否以字符串传入 WASM。** 传数值会静默产出损坏文件。
3. **是否用 `require()` 加载 WASM 胶水代码。** 表现为进程静默挂住无报错，必须改用 vm 沙箱。
4. **`.wasm` 文件是否存在且与 `.js` 同目录。**
5. **下载的是否是封面图而非视频。** 检查文件大小与 `Content-Type`，几十 KB 的 JPEG 说明取错了地址。

验证解密成功的判据：文件头应为 `00 00 00 20 66 74 79 70`（`ftyp` 盒），`file` 命令识别为 `ISO Media, MP4 Base Media`，`ffprobe` 能读出视频与音频流。

## 无 API key 的替代路径

不要因为缺 key 就判定任务无法完成，按成本从低到高提供三条：

**其一，请用户录屏。** 微信里播放并录屏，导出 mp4 发来，走管道 B。一至两分钟的口播内容录屏损失极小，与解密原片无实质差别。零成本零配置，适合偶尔处理少量内容。

**其二，搜同源转载。** 技术评测、行业观点类内容常多平台分发，用标题在 B站/抖音/公众号搜索，命中后走管道 C 或 D。对多平台分发的账号成功率较高。

**其三，请用户本机批量导出。** 安装 `qiye45/wechatVideoDownload`（GitHub 5.6k stars），在微信中播放时自动抓取并解密，直接得到可播放 mp4。适合一次性处理某账号全部历史内容，导出后打包走管道 B 批量转写。

仅当用户需要长期、批量、自动化处理时，才建议配置付费 API key。

## 平台限制对照

| 平台 | 网页端可得 | 需要什么 |
|------|-----------|---------|
| 视频号 | 标题、账号、发布日期、互动数据、封面图 | 视频流需第三方 API 或客户端侧导出 |
| YouTube | 全部内容 | 无需下载，直接分析 |
| B站 | 通常可取 | 一般无需特殊处理 |
| 抖音 | 部分受限 | 视情况需 API |

视频号即便无法取得视频流，**已可得的元数据仍有独立价值**：标题文案是选题与句式样本，互动数据可做传播特征分析。此时应按「情报层」入库，而非判定任务失败。

## 情报层的用法

当本次任务未能取得逐字稿时（例如用户不愿配置 API key 且不方便录屏），元数据仍可产出三类价值：

标题文案本身是顶级选题样本，例如「国产品牌正在揽胜化、卫士方盒子化、保时捷化，中国汽车工业正陷入'审美主权'危机」，其「X化Y化Z化」三连排比加造词的结构可直接复用。

互动数据可反推内容形态。**转赞比（转发数/点赞数）是关键指标**：比值接近或超过 1 说明是强观点驱动转发，用户愿意转发表态而非仅点赞认可。实测样本：某财经号内容转发 1.4 万对点赞 7816（转赞比 1.8）；某创业教育号内容转发 110、收藏 113 对点赞 18（**转赞比 6.1**），后者含明确的自我归类判断（「你是手艺人还是操盘手」），促使观众收藏自省与转发表态。

定期采集对标账号元数据可形成选题雷达。按 OPRASE 归类，这属于 R 层（当下业务数据），不是 P 层（方法论）。
