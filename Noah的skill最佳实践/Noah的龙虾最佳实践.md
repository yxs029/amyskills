### **二、 Nova的主讲内容**

#### **第一部分：个人背景与成果展示**

- **背景：** 营销出身，无技术背景，去年9月前对AI还是“求佛式”使用。通过系统学习，现已能完成Web开发、AI Agent设计和流程化项目。
- **成果展示（虾池子）：** 介绍了他本地部署的OpenClaw系统中四个分工明确的Agent：
    1. **鸿运：** 总管，负责长任务管理和协调，日常任务是在Motbook平台发帖。
    2. **露露：** 专职调研Agent。每天从全网（RSS、微博、知乎等）收集数据，存入SQLite数据库，并生成包含数据概览、热门话题聚类的每日调研报告和网页。
    3. **比比：** 专职写作Agent。被设定为“有作家灵魂的自媒体写手”。单篇文章创作需经过10个步骤、40多个确认点，每天可写10-20篇文章。
    4. **图图：** 专职配图Agent。根据文章内容精准配图。
- **实战成果：** 利用这套Agent系统，帮助一个濒死的头条账号在一个月内成长为“头条新锐创作者”。
- **开源承诺：** 宣布将分享会上提到的所有技能（Skills）、工具和流程全部开源。

#### **第二部分：龙虾入门指南（避坑与选型）**

- **解决“怕”的问题：** 提高认知，快速搜索最佳实践。
- **版本选型三大类：**
    1. **云厂商镜像版：** 功能接近原版，但不能操作本地文件，适合有一定技术背景的用户。
    2. **云端托管/SaaS版（如腾讯Q-Call）：** 一键安装，设置简单，但功能可能受限（如常无法使用浏览器工具）。**最适合新手**。
    3. **完全本地部署版：** 功能最强（满血原版），但对安全和操作要求最高。
- **安装与设置技巧：**
    - **安装依赖：** 注意新版本（2026年3月2日后）需要GitHub SSH验证。
    - **小妙招：** 用豆包、Kimi等大模型指导安装；或使用Cursor、Claude Code等AI编程工具协助部署。
    - **设置差异（国内用户）：** 首次设置（Onboarding）时，注意大模型选择（可用国内模型）、Web搜索和通信渠道可跳过，快速完成。
    - **版本建议：** **不要追新版本**，推荐使用2月26日或3月13日的稳定版。新版本（如3月22/23日）可能存在前端、插件兼容性问题。
    - **工具替代：** 提供了用 `gina.ai` 等工具替代原版需付费的 `web_search` 和 `web_fetch` 的方法。

#### **第三部分：如何设计你的第一个Agent**

- **设计核心四文档：** 在创建Agent时，需要想清楚并写入对应文档：
    1. **Identity（身份）：** 他是谁？性格？与你的关系？核心任务？
    2. **Soul（灵魂/价值观）：** 他的信仰、做事风格。
    3. **Scope（工作范围）：** 工作方式、流程、必须做/不能做的边界。
    4. **User（用户画像）：** 在他眼中，你是谁？你的喜好和期望。
- **关键认知转变：** **Agent不是Chatbot（聊天机器人）**。应将其视为**某个领域的专家伙伴**，而非全能问答机。
- **新手建议：** 从职责单一的小助理开始（如待办事项、健康提醒），熟练后再创建专业Agent。**“越全能可能意味着越无能”**。
- **提示词原则：** 把他当成一个聪明但毫无工作经验的新人，需要通过文档为其建立完整的岗位认知和操作规程。

#### **第四部分：为Agent赋能——Skills（技能）**

- **Skills的重要性：** Skills是Agent能力的延伸，相当于给专家配备工具（如浏览器、办公软件、知识库管理器）。
- **获取Skills的四大渠道：**
    1. **OpenClaw内置Skills：** 安装后优先启用 `cloud_hub`、`github`、`skill_creator` 这三个技能。
    2. **官方市场 CloudHub.ai：** 有丰富的技能列表，如 `summarize`（总结）、`skill_vetter`（安全扫描）、`agent_browser`（浏览器操作）。
    3. **GitHub：** 寻找更重、更专业的开源项目（如小红书MCP）。
    4. **大厂插件 & 社区知识库：** 关注飞书、微信等官方插件，并充分利用“一堂”等学习社区共享的资源。
- **安全提示：** 安装公开Skill前，建议用 `skill_vetter` 进行安全扫描。

#### **第五部分：从简单任务到复杂工作流**

- **复杂任务的挑战：** 与实际场景紧密相关，有严格的输入-处理-输出要求，常需拆解为子任务，需要进行**任务链条设计和管理**。
- **设计思维框架（两个三角形）：**
    - **人类三角：** 任务审美是否够高？是否有好的任务管理体系？是否发挥了人类的创造力？
    - **AI三角：** 场景是否适合AI做？我的AI基本功是否够？AI是否有足够的数据和方法论支持？
- **案例详解：自媒体内容生产流水线**  
    Nova以帮助自媒体账号为例，拆解了其用Agent实现的完整工作流：
    1. **调研阶段（露露负责）：**
        - **痛点：** 原有技能数据源偏国外、字段不统一、文件管理混乱。
        - **改造：** 整合国内外150+RSS源；覆盖微博、知乎等国内平台热榜；用SQLite数据库统一存储管理数据（半个月1.2万条数据仅60MB）。
    2. **选题阶段：**
        - **思路转变：** 从“严格筛选”变为“置信度筛选”，利用AI的产能优势。
        - **流程：** 从每日数据中根据标签热度筛选前50个话题 -> 从中再精选15个写作选题 -> 对每个选题进行**原文链接验证和关键信息抓取**，确保时效性和准确性。
    3. **写作阶段（比比负责）：**
        - **精细流程（10步）：** 查看选题 -> 验证摘要 -> 分析受众 -> 确定故事线 -> 加载写作风格指纹 -> 必要调研 -> 分章节撰写 -> 配图预留 -> 人工润色（24项检查）-> 格式检查 -> 自检确认 -> 最终交付。
        - **深度文章流程：** 额外增加深度调研报告、大纲撰写等环节。
        - **技巧：** 任务开始前，让Agent**多读一遍Soul文档**，能显著提升执行效果。
    4. **配图阶段（图图负责）：**
        - **流程：** 发现文章需配图位置 -> 解析内容 -> 区分头图（必须自生，避版权）和内插图（可搜索或自生）-> 按规则生成。
- **自动化与进化：任务管理系统（Open X-Card）**
    - **痛点：** 长流程任务中，AI的不确定性会累积，导致最终结果出错。现有工具缺乏对任务**左右边界**（输入输出格式、文件路径等）的硬性约束。
    - **解决方案：** Nova开源了 **`Open X-Card`** 项目。
        - **核心思想：** 将Agent的能力、资源、技能封装成**单元型任务卡片（EC Card）**。每张卡片**明确定义**了所需的技能、依赖的文件、输入输出路径和完整步骤。
        - **与Skill的区别：** EC Card是**多个Skills + 文件依赖 + 固化流程**的集合，通过硬性约束确保了任务执行的稳定性。
        - **长任务管理：** 配合 `long_task_system` 技能，可以用多张EC Card组合成复杂工作流，并通过一个“驾驶舱”网页监控执行进度。
    - **演示：** 现场演示了如何使用该系统，让“鸿运”调用“露露”，通过三张EC Card自动完成每日调研任务，全程无需人工干预，10分钟内产出包含2000多条数据的调研报告。

#### **第六部分：答疑与鼓励**

- **费用与配置：** Nova主力使用Kimi（699元/周套餐），用量约70-80%。他认为本地部署长期看成本最低，但轻度用户直接用云端SaaS版更省心。他的演示环境是几年前的老Mac（8G内存），证明对硬件要求不高。
- **多Agent协作：** 建议通过**文件**而非直接对话（session sponge）进行协作，避免token浪费和聊天跑偏。
- **控制Token消耗：** 设置明确的职责边界（不当Chatbot用）；利用OpenClaw的fallback机制（主模型失败时自动切到更便宜的备模）。
- **新手鼓励：** 强调即使现在开始学习，在全球范围内也属于前沿的少数人（可能在前6%），完全来得及，要有信心。
- **其他工具：** 提到扣子（Coze）可用于调用现有工作流，但OpenClaw几乎能实现其所有功能；对于代码开发，建议用Cursor等专业IDE；提到了GitHub上热门的自动视频剪辑项目 `money_printer`。
