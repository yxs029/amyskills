# WeChat Article Compliance Checker

## Inputs to collect

从用户输入提取以下信息；缺失则按默认推断（不要为细节反复追问）：

- 原文（`.md` / `.txt` / `.docx` / 纯文本）—— 缺失则提示用户提供
- 文章所属行业（一般 / 医疗 / 食品 / 金融 / 教育）—— 缺失则按"一般"处理，仅用通用规则
- 是否需要输出 `.docx` —— 缺失则默认只输出 Markdown
- 是否需要保留原文事实/数据/引用 —— 缺失则默认保留（不删除证据，只改语气）
- 是否使用 AI 辅助创作（是 / 否 / 未知）—— **必须明确采集，不要默认"未知"跳过**。
  - 已知"是/否"：直接据实给出声明建议。
  - "未知"：由模型依据文本痕迹评估，并在报告中标注"评估依据：文本特征"。
  - 无论哪种，均在报告中给出声明建议强度：**建议声明 / 必须声明且需重构 / 无需声明**。

## Procedure

> **双轨设计**：Step 2（硬性合规）与 Step 3（低创作度与 AIGC 原创度评估）是**平级的两轨**，
> 一篇公众号文章发布前必须两轨都过。硬违规是封号/删文级风险；低创作度是限流级风险。

### 0. 输出文件命名规则（版本递增）

**模板**：`{类型}_v{版本号}_{原文件名}.md`

| 类型 | 文件名 |
| --- | --- |
| 合规修订版 | `合规版_v{版本号}_{原文件名}.md` |
| 标红检查版 | `违禁词标红版_v{版本号}_{原文件名}.md` |
| 合规检查报告 | `合规检查报告_v{版本号}_{原文件名}.md` |

**版本号取值规则**（按优先级，命中即停）：

1. **用户显式指定**（最高优先）—— 用户说「用 v3」「覆盖 v2」「从 v1 重来」等指令时，严格按用户给的数字；显式说"覆盖"时需先确认。
2. **默认递增** —— 未指定时，扫描输出目录，匹配所有 `{类型}_v{N}_{原文件名}.md`，取最大 N → 输出 v(N+1)。
3. **首次扫描** —— 目录里没有任何同原文件名的产物 → 默认 v1。

**计数边界**：

- **按原文名分组计数**：`{类型}_v*_原文件名.md` 里"原文件名"完全相同的算同一组，跨原文不共享版本号（A 的 v1 与 B 的 v1 共存）。
- **跨类型共享计数**：同一批次三份文件版本号必须一致（v1 合规版 + v1 标红版 + v1 报告 = 同一轮扫描）。
- **`<原文件名>` 保留完整**：原文标题里的日期、来源、标签（如「V3」「纯净版」「来自【得到大脑】」等）全部保留，仅在开头添加 `{类型}_v{版本号}_` 前缀。
- **忽略旧式后缀命名**：原 `[原文件名]_合规版.md` / `[原文件名]_违禁词标红版.md` / `[原文件名]_合规检查报告.md` 不参与递增计数（旧版文件保留不影响新版从 v1 开始）。

**示例**（原文 `7月31日  专利壁垒——爱迪生与好莱坞（三维度校准版）V3（纯净版）-2026年07月27日-来自【得到大脑】.md`）：

- 首次扫描 → `合规版_v1_7月31日  专利壁垒——爱迪生与好莱坞（三维度校准版）V3（纯净版）-2026年07月27日-来自【得到大脑】.md`
- 改了一轮再扫 → 目录已有 v1，输出 v2
- 用户说"用 v5" → 直接输出 v5（无需提示）
- 用户说"覆盖 v3" → **必须先 AskUser 确认覆盖**，再写 v3

### 1. 读取文章与规则（含元信息采集）

读取用户提供的文章：

- `.md` → 直接保留 Markdown 结构
- `.txt` / 纯文本 → 按段落拆分，转为 Markdown
- `.docx` → 提取段落与标题层级，转写为 Markdown（保留 # 标题层级与列表）
- 若文章带图片（Markdown `![](...)` 或 docx 嵌入图）→ 提取 alt 文本作为检查依据；图片本身不参与检查，但需记录"是否存在以 AI 图片为主体且配文无增量"的风险信号

同时采集创作度元信息（是否 AI 辅助、有无原创素材），用于 Step 3 与报告声明建议。

读取前必须参考：

- `references/banned_words_checklist.md`：违禁词分类与替换建议（硬性合规）
- `references/low_quality_content_checklist.md`：低创作度 / AIGC 原创度评估规则（含评分权重表）

### 2. 硬性合规检查（第一轨）

逐段扫描所有内容，识别以下风险（不仅关键词匹配，还要看上下文语义）：

| 风险类别 | 典型表现 | 重点 |
| --- | --- | --- |
| 极限词 | "最 / 第一 / 顶级 / 100%" | 广告法第 9 条 |
| 虚假承诺 | "包过 / 包治百病 / 稳赚不赔" | 广告法 + 平台规则 |
| 医疗 / 健康 | "治愈率 / 根治 / 无副作用" | 医疗广告管理办法 |
| 食品 / 保健 | "替代母乳 / 特效" | 食品安全法 |
| 金融投资 | "高收益 / 保本 / 公开荐股" | 证券法 + 平台规则 |
| 诱导分享 | "不转不是中国人 / 集赞" | 微信平台运营规范 |
| 变体规避 | "拼音缩写 / 谐音 / 拆字" | AI 语义分析重点打击 |
| 政治 / 迷信 | 领导人姓名不当 / 封建迷信词 | 绝对禁区 |
| 隐私侵权 | 身份证 / 联系方式 / 照片 | 民法典 + 平台规则 |

每条风险记录至少包含字段：

- `original`：原词 / 表达
- `position`：行号或段落号或标题层级
- `level`：高 / 中 / 低
- `category`：风险类别
- `reason`：风险原因（引用具体法规或规则）
- `suggestion`：替换建议（保持原意、降级表达）

### 3. 低创作度与 AIGC 原创度评估（第二轨）

与 Step 2 平级，是发布前必须过的另一轨。参考 `references/low_quality_content_checklist.md`，逐篇做七项软质量评估：

1. **信息密度**：勾"自检 5 问"，给 高/中/低（权重最高）。
2. **模板化 / 同质化**：扫标题公式黑名单 + 段落结构雷同 → 模板化程度（无/轻微/高）。
3. **AI 痕迹**：数词库命中密度 → 明显/轻微/无。
4. **搬运 / 洗稿**：是否大段复述站外内容、截图搬运、缺少个人观点与增量。
5. **非真人自动化风险**：是否 AI 生成主体 + 批量/定时发布、是否推广"AI 代运营/AI 批量发文"服务（2026.3.27《微信公众平台运营规范》新增专项条款）。
6. **AI 辅助声明建议**：依据 Inputs 的"是否 AI 辅助"与文本特征，给声明建议与位置（文首/文末/图注）。
7. **加权评分**：按 checklist「七、加权评分权重表」算总分 → 低创作度风险 高/中/低。

> 重要边界：本 skill 只暴露"信息增量与原创度"问题，**不做 AI 痕迹消除**。
> 若实际使用方式是"AI 生成全文 → 几乎不改 → 批量定时发布"，无论本 skill 如何升级，
> 平台都会判定为"非真人自动化创作"。核心解法仍是：真人经验 + 信息增量 + AI 当工具而非作者。

### 4. 生成 Markdown 标红检查版

生成一份 Markdown，保留原文结构，把**硬性合规**风险表达用 HTML 内联样式标红：

```markdown
<span style="color:red;font-weight:bold">风险表达</span>
```

> 低创作度风险（如 AI 空话、模板化）**不在正文标红**（避免误伤文风），统一汇总到报告「低创作度风险评估」章节。

> 同一段多个风险词：按"长词优先"顺序逐个标记，避免短词替换长词时嵌套错位。

命名建议：`违禁词标红版_v1_<原文件名>.md`（首次扫描）

> 版本递增规则与覆盖确认流程详见 Step 0。`<原文件名>` 保留完整的原文标题（含日期、来源、其他标签）。
> 例（首次扫描）：`7月31日  专利壁垒——爱迪生与好莱坞（三维度校准版）V3（纯净版）-2026年07月27日-来自【得到大脑】.md` → `违禁词标红版_v1_7月31日  专利壁垒——爱迪生与好莱坞（三维度校准版）V3（纯净版）-2026年07月27日-来自【得到大脑】.md`

文件末尾附说明：

```markdown
---

## 风险提示

本文共检测到 N 处需复核表达。完整修改建议请查看合规检查报告。
```

### 5. 生成 Markdown 合规修订版

把硬性合规风险表达替换为更客观、审慎、可验证的表述。**替换原则**：

1. **保持原意**：观点、立场不改动
2. **保持文风**：句式长度、语气接近原文
3. **保持结构**：标题层级、引用、表格、图片路径、参考链接全部保留
4. **不改证据**：外部事实、数据、引用来源不删除，只改判断语气
5. **不主动加图**：标红版里没有的图，合规版也不补

文件开头附说明：

```markdown
> 说明：本版本已按检查建议替换风险表达，尽量保持原意并降低公众号发布风险。
```

文件末尾附"替换对照表"：

```markdown
## 替换对照表

本次共替换 N 处风险表达。

| 序号 | 原词/表达 | 替换后表达 | 风险类别 |
| ---: | --- | --- | --- |
| 1 | 全网第一 | 具有一定代表性 | 极限词 |
| 2 | 包治百病 | 可能有助于改善部分体验 | 医疗功效承诺 |
```

命名建议：`合规版_v1_<原文件名>.md`（首次扫描）

> 版本递增规则与覆盖确认流程详见 Step 0。`<原文件名>` 保留完整原文标题。

### 6. 发布决策闸（综合两轨，供 Step 7 报告引用）

综合 Step 2（硬违规）与 Step 3（软质量）结果，得出明确发布结论：

| 情况 | 结论 | 说明 |
| --- | --- | --- |
| 存在高 / 中风险硬违规 | **需修改后发** | 先改硬违规，否则有封号 / 删文风险 |
| 硬违规低或零 + 低创作度=高 | **不建议发 / 需大改** | 限流风险高，需补信息增量或重构 |
| 硬违规低 + 低创作度=中 | **需修改后发** | 补个人观点/来源/可落地方法，建议声明 AI 辅助 |
| 硬违规零 + 低创作度=低 | **可发** | 仍建议标注 AI 辅助（若使用了 AI） |

> 注：「低创作度 = 高 / 中 / 低」对应的加权总分阈值，详见 `references/low_quality_content_checklist.md` 第七节「加权评分权重表」。

输出：发布结论（可发 / 需修改后发 / 不建议发）+ 一句话理由 + 优先处理项。

> 注意：决策闸只给"建议"，不替平台下判决。若低创作度=高且疑似"非真人自动化创作"，
> 必须明确提示这属账号维度风险，单篇改写无法根本解决。

### 8. 交付结果

默认附件顺序：合规修订版 → 标红检查版 → 检查报告。

交付消息简要说明：

- 硬性风险总数（高 / 中 / 低分级）与主要风险类别（Top 3）
- 低创作度风险等级（高 / 中 / 低）与核心问题（如同质化 / AI 痕迹明显 / 信息密度低）
- **发布决策结论**：可发 / 需修改后发 / 不建议发 + 一句话理由
- 是否建议标注 AI 辅助创作
- 三个 Markdown 文件路径

## Output contract

每次执行必须交付：

- **三份 Markdown**（版本号必须三份一致）：
  - `合规版_v{N}_{原文件名}.md`
  - `违禁词标红版_v{N}_{原文件名}.md`
  - `合规检查报告_v{N}_{原文件名}.md`
  - `{N}` 取值见 Step 0「版本号取值规则」：默认 v1，按同原文件名目录中既有最大 N 自动递增；用户显式指定时按用户指令。
  - `<原文件名>` 保留完整原文标题（含日期、来源、标签）。
- **双轨结果**：硬性合规风险分级统计 + 低创作度加权评分与风险等级
- **替换对照表**：合规版末尾附"原词 → 替换后"对照
- **发布决策结论**：可发 / 需修改后发 / 不建议发 + 理由（决策闸产物）
- **默认不输出**：`.docx` / `.pdf` / 评分表（除非用户明确要求）
- **保留原文事实**：不删除证据，仅改语气

## Failure handling

- **原文 < 100 字** → 不暂停扫描，标记为"低创作度高风险预检"：信息密度直接判低，
  仍允许后续硬性合规检查，但在报告中强提示"信息量不足极易被判定为低创作度，不建议直接发布"，
  并给出改进方向：补充背景、观点、数据、案例、个人经验。
- **扫描零风险** → 仍生成三份文件（标红版 + 合规版 + 报告），报告里写"本次扫描未发现明显违规表达"，
  但提醒"AI 语义分析有边界，建议用户人工复核"；若同时信息密度低 / AI 痕迹明显，仍需在「低创作度风险评估」章节标出。
- **原文带图片** → 提取 alt 文本与图片说明文字作为检查对象；图片本身不直接扫描，但需记录"是否以 AI 图片为主体且配文无增量"的信号。
- **用户明确要求 docx** → 输出 Markdown 后追加一份 `.docx`（可调起 docx skill 生成，或手动转写），但默认仍以 Markdown 为主
- **用户原文是新闻 / 学术 / 法律合同** → 提醒"本 skill 面向公众号内容合规，新闻 / 学术 / 合同等场景适用不同规则，请确认是否继续"

## Examples

**Input A（硬性合规）**：用户贴 500 字公众号软文，含"全网第一""包治百病""稳赚不赔"等高风险表达。

**Output A**：

- `合规版_v1_<原文件名>.md`：替换 5 处风险表达，保留原文段落结构和数据
