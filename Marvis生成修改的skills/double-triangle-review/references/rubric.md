# 评分量化体系(1-5 分制)

每道题采用 **1-5 分李克特量表**(Likert Scale),根据描述的契合度打分:

## 通用打分标准

| 分值 | 标签 | 含义 |
|---|---|---|
| **1** | 完全不符合 | 我几乎从不这样做 / 完全不认同 |
| **2** | 基本不符合 | 偶尔做 / 不太认同 |
| **3** | 中立 | 说不准 / 视情况而定 |
| **4** | 基本符合 | 经常做 / 基本认同 |
| **5** | 完全符合 | 我一直这样做 / 完全认同 |

**统一原则**:
- **直觉作答**:不要反复纠结,你的第一反应最准
- **看行为不看意图**:问自己"我**做过**吗",而不是"我**想做**吗"
- **参照最近 3 个月**:不要拿"曾经"和"现在"混着答

## 反向题(reverse: true)

部分题是**反向题**,需要翻转计分:

```
你的答案:  1  2  3  4  5
计分转换:  5  4  3  2  1   (即 6 - 你的答案)
```

例如:
- 题 17:"我的知识资料分散在多个平台中" → reverse=true
- 你答 4(基本符合)= 你的真实情况是分散得很厉害
- 计分时转换:6 - 4 = **2 分** → 体系(S1)分数低,因为 S1 是"散点管理"

## 子模块分 = 子模块内所有题的平均分

```
sub_score = (sum of answered scores) / (number of questions in sub)
```

范围:**1.0 - 5.0**,保留 1 位小数。

## 通过分数线 = 3.5

子模块分数 **>= 3.5** 视为"通过(passed)",否则"未通过"。

> 3.5 不是"刚好及格",而是"基本稳定执行"。低于 3.5 表示尚未建立稳定习惯。

## 段位定义(以子模块为单位)

子模块按通过分数线划分段位:

| 子模块分数 | 段位标签 | 含义 |
|---|---|---|
| **>= 3.5 且 order=1 (第一个子模块)** | 段位 1 | 已通过基础模块 |
| **>= 3.5 且 order=N (第 N 个)** | 段位 N | 当前通过到第 N 个 |
| **< 3.5** | 未建立 | 当前所有子模块都未稳定 |

> **举例**:A1-A4 四个子模块,你 A1=4.5、A2=4.0、A3=3.6、A4=2.8,则审美段位 = **A3** (因为 A4 没通过,最高的已通过是 A3)。
>
> 又例:A1=4.5、A2=4.0、A3=4.2、A4=3.8,则审美段位 = **A4**(全过)。

## 维度分 = 子模块分的平均

```
dim_score = average of all sub_scores in this dimension
```

## 综合分 = 所有子模块分的平均(简化)

```
overall_score = average of all 27 sub_scores
```

> 注意:不要用"加权综合分"。本 skill 默认**等权**,因为双三角的设计者认为 6 维度同等重要。如果用户业务场景需要加权,允许自定义。

## 段位快速判定(实战)

不用每次都画雷达图,**记住 3 条线**就够了:

- **3.5 线**:基础通过线。低于就是"未建立",高于就是"已建立"。
- **4.0 线**:稳定执行线。高于就是"可输出、可教学",低于就是"自己能用、难以解释给别人"。
- **4.5 线**:领先线。高于就是"行业头部、可以开课 / 出书",低于就是"专家水平"。

## 评分实施注意事项

### 1. 自评 vs 他评

- **自评**:你对自己的打分,适合快速复盘
- **他评**:让同事/朋友根据你的实际行为打分,更准但更慢
- **数据评**:用日志、代码、笔记等"事实数据"反推分数,最客观但门槛高

### 2. 复评周期

- **初评**:第一次完整做一遍,定位起点
- **3 个月后**:看哪些子模块涨了,锁定涨的因素
- **半年后**:看哪些维度有"跨级跳",找到杠杆子模块

### 3. 评分诚实度

不要因为想要"段位高"就放水,也不要因为"谦虚"就压分。**对照"我最近 3 个月做了什么"**,实事求是。

## 反模式

- ❌ 全打 4 / 全打 5(无区分度)
- ❌ 全打 1 / 全打 2(自我贬低)
- ❌ 每题纠结 5 分钟(违背"第一反应"原则)
- ❌ 一周内反复测分取平均(分数会因"刚刚学到一个东西"而虚高)

## 高阶用法:自评 + 证据链

打完分后,挑**最低分**的 3 个子模块,**用证据回填**:

```
子模块 K3 智能体与RAG: 我打了 3.0 分
证据:
  - 我用 LangChain 做过 1 个 RAG demo (项目: xxx)
  - 但生产环境没部署
  - 没有真正复盘过 RAG 评估指标

→ 结论:3.0 分合理,要从"demo"走到"生产"才能上 4.0
```

这种**"分数 + 证据"**的二段记录比单纯分数更有价值,可作为下次复评的对比基线。
