# 场景迭代建议报告(报告 2 模板)

> 报告 2 是"喂给 AI 直接跑下一轮"的优化建议。结构:基于本次复盘的 6 要素分数,**为下一轮类似场景协作提供具体的、AI 可执行的改进指令**。

## 设计原则

1. **可执行**:每条建议都能直接复制给 AI 当 system prompt / user prompt
2. **场景化**:建议针对**这次复盘的具体场景**(不是泛泛的)
3. **双向**:同时给"AI 下一步做什么"+"人类下一步做什么"
4. **优先级**:有 P0 / P1 / P2,避免一次堆 20 条建议

## 报告 2 完整结构

```markdown

| 下一轮预计耗时 | <2 天(目标)> |

## 上一轮 6 要素得分速览

| 审美 | 🔵 进阶段 | 35% | 输出物格式清晰,但不够"惊艳" |

**问题描述**: <体系段位低,返工多,无 runbook>

**人类下一步应该做的**:
- [ ] 写 1 份 runbook 放在 SKILL_REFERENCE.md

Before writing any code:
1. Check if a runbook exists at SKILL_REFERENCE.md
2. If yes, read it FIRST and identify the relevant section for current task
3. Identify potential failure modes from the runbook
4. Pre-plan: outline the steps in 3 sentences BEFORE executing
5. Execute step-by-step with checkpoints every 2 steps

Reporting format:
- After each checkpoint, output: "STEP N DONE: <what was completed> | NEXT: <what's coming> | RISK: <any new risks identified>"
```

**成功验证标准**:
- [ ] runbook 完成
- [ ] 下一轮 AI 跑项目时,前 5 步零返工

---

## 报告 2 与报告 1 的关系

```
报告 1 = "我们做得怎么样"
  → 6 要素分数 + 雷达图 + 段位 + 90 天成长主线
  → 用于复盘和自我认知

报告 2 = "下一轮怎么做得更好"
  → P0/P1/P2 改进建议 + 可执行 prompt
  → 直接喂给 AI 下一轮
```

**两者互补**:报告 1 是"诊断",报告 2 是"处方"。

---

## P0/P1/P2 优先级判定

| 等级 | 标准 |
|---|---|
| **P0** | 阻碍下一轮跑通 / 已经造成 2+ 次返工 / 影响范围 > 50% 工作量 |
| **P1** | 提升效率 / 减少返工 50% / 影响 1-2 个具体场景 |
| **P2** | 战略性优化 / 6 个月后才见效 / 锦上添花 |

每份报告 2 至少 1 条 P0,不超过 3 条 P0。

---

## 报告 2 的产出方式

报告 2 **不靠模板填空**,而是由 LLM 基于报告 1 的 6 要素得分 + 上一轮的具体场景,生成定制化的建议。

实现路径:
1. 输入:报告 1 的子模块明细 + 场景元数据(场景名 / 上一轮耗时 / 关键观察)
2. LLM 调用 `scripts/eval_prompt.md` 的"迭代建议生成 prompt"
3. 输出:报告 2 的 markdown 全文

详见 `scripts/auto_assess.py`。

## 高级用法:多轮迭代追踪

如果同一场景跑了 3 轮,可以:
- 把 3 份报告 1 + 报告 2 按时间序列存档
- 画"场景迭代曲线图":x 轴是轮次,y 轴是 6 要素分数
- 沉淀"我们这个场景的合作方法论"v1 / v2 / v3

这是**真正的"飞轮"**——每一轮迭代都比上一轮更默契。
