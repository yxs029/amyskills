# 输出风格指南

> 这份指南定义 cancer-research skill 产出报告的视觉/写作规范。目的是
> 让多份报告之间风格一致,医生/患者扫读时能快速找到信息。

## 总体定位

- **读者**:主治医生(看循证)+ 患者/家属(看决策)
- **场景**:每周四自动更新;医生会在 1-3 分钟内扫读最新要点
- **优先级**:**决策密度 > 学术严谨 > 行文优美**

## Markdown 渲染规范

### 标题层级

- 报告主标题:`# {癌种}{分期}{分册名}调研报告`
- 一级章节:`## {N}.{章节名}`(必须带数字,便于引用)
- 二级章节:`### {N.M}{小节名}`
- 三级章节:`#### {N.M.K}{细分点}`

**为什么带数字**:医生/患者在不同时间点讨论时会说"看一下第二部分第三节"——
带数字便于定位。

### 表格优先于段落

每张表必须:
- 第一列是分类(药物/方案/研究/证型)
- 关键数据列加粗(`**X 个月**`)
- 必带来源列(DOI/摘要号/期刊年)

**例**:
```markdown
| 药物 | 中位 OS | 中位 PFS | 副作用 |
|------|---------|---------|--------|
| **呋喹替尼** | **9.3 个月** | 3.7 个月 | 肝脏毒性最低 |
```

**避免**:把 5+ 个数据点写进一段散文,医生要 30 秒才能找到关键数字。

### 关键标记符号(全文统一)

| 符号 | 含义 | 用法 |
|------|------|------|
| `🚨` | 重大更新/突破 | 章节标题前 |
| `🆕` | 本次新增内容 | 表格/列表项前 |
| `⚠️` | 警告/重要提示 | 注意事项前 |
| `💡` | 提示/小贴士 | 辅助说明前 |
| `📍` | 地址/位置 | 医院地址前 |
| `📞` | 联系电话 | 联系方式前 |
| `🌐` | 网址 | 链接前 |
| `🏥` | 医院/机构 | 机构名前 |
| `**加粗**` | 关键数据/术语 | 数据列、关键药名/研究名 |
| `*斜体*` | 引文/出处 | (少用) |

### 引用与可追溯性

每条研究/数据必须可追溯。引用格式:

```markdown
- **{研究名}**({年份}) —— {期刊/会议} {摘要号或 DOI}
```

例:
```markdown
- **BREAKWATER 队列 3**(2026) —— ASCO 2026 摘要 13
- **CAPability-01**(2024) —— Nature Medicine DOI:10.1038/s41591-024-...
- **CSCO 结直肠癌诊疗指南 2026 版**(2026 年 4 月) —— CSCO 官网
```

## 数字与统计表达

### 必须保留的精度

- **P 值**:写到 3 位小数(P=0.049 写 0.049,不要 0.05)
- **置信区间**:`95% CI 0.6-0.9` 完整保留
- **HR/RR**:`HR 0.44 (95% CI 0.32-0.61)`,不省略括号
- **百分比**:小数点后 1 位(ORR 46.9% 不要写 47%)
- **生存期**:`mPFS 15.2 个月`、`mOS 41.1 个月` 完整单位

### 模糊数据的处理

- 没有具体数字:"在多项研究中显示出获益趋势",**不编造数据**
- 样本量小:"(N=23,小样本研究,需谨慎解读)"
- 多研究数据矛盾:"研究 A 显示...研究 B 则...可能与...差异有关"

## 中医分册特殊规范

### 方剂表述

- **基础方**:`**{方剂名}**加减` + 列出主药(通常 4-8 味)
- **不写剂量**:剂量由临床中医师根据患者情况决定,报告中不直接给 g 数
- **引用源**:`来源:{教材/共识/期刊}`(如《中医内科学》第 9 版、《中医肿瘤
  学》专家共识)

### 中成药表述

- 必须用**国家药监局批文/说明书**上的"功能主治"原文
- 不二次解读"对 XX 癌有效"
- 标注:批准文号 + 厂家(若仅一家独家)

### 中医证型表述

- 证型名用**标准术语**:`湿热蕴结`、`脾虚湿阻`、`瘀毒内阻`、`气血两虚`、
  `肝肾阴虚`(避免"湿热下注""热毒炽盛"等非标准同义)
- 主症用 3-5 个可观察的症状,不写舌脉象具体形态(让主治中医师自己看)
- 提醒:`以个人舌脉为准,本报告不替代中医师诊断`

## 西医分册特殊规范

### 药物名称

- **首次出现**:中英文 + 商品名
  - `呋喹替尼(Fruquintinib,商品名爱优特®)`
- **后续**:可只写英文 INN 或中文
- **避免**用只有药企内部代号

### 临床试验表述

- **试验名 + 期别 + 状态**:`**CAPability-02(III 期)**`
- **关键数据**:mPFS / mOS / ORR / DCR / HR / P 值
- **不引用未发表的 II 期单臂数据**作主要推荐依据

### 基因/分子表述

- 用 **HGNC 官方基因名**:`KRAS`、`BRAF`、`HER2`(不要 KRas / Kras)
- 突变用 **标准写法**:`KRAS G12C`、`BRAF V600E`
- 蛋白:`HER2/ERBB2` 蛋白、`KRAS` 蛋白

## 报告头(顶部元数据)

每份报告固定顶部:
```markdown
# {标题}

> **更新时间**:每周{周期}自动刷新(首次:{首发日期},最近更新:**{本次日期}**)
> **免责声明**:本报告仅供与主治医生讨论参考,不构成治疗建议。
```

## 报告尾(底部)

固定底部:
```markdown
---

## ⚠️ 免责再强调

本报告基于截至 {本次日期} 的公开信息整理;医学进展日新月异,任何用药/
方案调整请在专业医生指导下进行。

报告作者:Mavis AI(cancer-research skill)
生成时间:{本次日期} {本次时间}
对应 cron:{cron_name 或 "用户手动触发"}
```

## 长度控制

### 完整报告(`full` 模式)

- **西医分册**:`800-1500 行` 是正常范围(覆盖靶向/免疫/放疗/手术/试验/共识)
- **中医分册**:`300-500 行` 较合适(分册本身章节少)
- **合集**:`1000-2000 行`(等于"西医 + 中医 + 协同点")

**超长处理**:超过上述行数 + 仍有新增内容时,优先把"本次更新重点"和
"上周要点"折叠区保留,正文按主题就近合并章节。

### 增量周报(`incremental` 模式)

- **目标长度**:`200-400 行`(约 3000-8000 字)
- **下限**:本周确实无重大进展时可短至 100 行,但"本周更新要点"和
  "临床策略影响"两节不能省略
- **上限**:不超过 500 行。如果一周内进展极多(如 ASCO 年会周),优先
  展开最重要的 3-5 项,其余在表格中一行带过
- **不要重复主报告内容**:周报不是缩写版主报告,只写"变化"和"新增"

### 设计理念

主报告是**全景参考文档**(编译基线),周报是**新闻通讯**(本周速报)。
两者合在一起才是完整的信息流:
- 患者/医生日常跟进 → 读周报(5 分钟扫完)
- 需要完整方案参考 → 读主报告(全景)
- 定期(月度/按需)→ 用 `compile` 模式把周报汇编进主报告,保持基线新鲜

## 自检清单(生成后)

- [ ] 顶部时间和免责声明都在吗?
- [ ] "本次更新要点"段是否基于实际检索,不是编造?
- [ ] 关键数据(OS/PFS/ORR)是否加粗 + 标注来源?
- [ ] 中医方剂是否都有文献来源?
- [ ] 表格是否带"来源"列?
- [ ] 与主治医生沟通清单是否 10-15 条具体可问的问题?
- [ ] 底部时间戳、cron 来源是否标注?
