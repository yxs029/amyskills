# 更新日志格式

> 每次 cron/手动跑完 cancer-research skill,需要追加一条到
> `<癌种>调研-更新日志.md`。本文件定义格式。

## 文件结构

```markdown
# {癌种}调研 - 更新日志

## {本次日期}({周几} {HH:MM})

### 本次更新({分册,如 西医报告 - 主题})
**触发**:`{cron_name}`(手动时写 `manual`)

**新增章节/重点**:
- 🚨 **{章节 A}** —— {要点}
- 🆕 **{章节 B}**:
  - **{子点 1}** —— {数据}
  - **{子点 2}** —— {数据}
- 🆕 **{章节 C}** —— {要点}

**更新内容**:
- 顶部时间戳更新为 {本次日期}
- {其他元数据变化,如 与主治医生沟通清单扩展到 14 项}
- 文件大小:{旧字节数} → {新字节数},行数 {旧行} → {新行}
- 新增章节:{列表}
- 参考文献表更新:增加 {列表}

**文件统计**:
- 西医报告:{旧行} → {新行}
- 中医报告:{旧行} → {新行}(若无更新写 "本次未涉及")
- 备份位置:`backup/{文件名}_{上次日期}.md`

### 笔记保存
- 西医报告 note_id=**{note_id}**(如已保存)
- 中医报告 note_id=**{note_id}**(如已保存;若未涉及中医写 "本次未涉及中医更新")

---

## {上次日期}({周几} {HH:MM})
... (上一条记录,保留以做历史轨迹)
```

## 关键规范

1. **每次追加在文件末尾**:不要中间插入,保持时间线顺序
2. **触发来源必填**:cron_name 写明,便于追溯哪次自动跑出问题
3. **数据要量化**:"新增 3 个章节"比"内容有更新"更可追溯
4. **备份路径必填**:`backup/` 目录是按日期保留历史版本
5. **note_id 必填**:`biji_sync=true` 时,note_id 是后续检索报告的关键

## 多分册时的处理

当一次跑两个分册(西医 + 中医),日志里**写一条主条目**,下面分两个
"### 子条目"分别说明西医和中医的更新。

```markdown
## 2026-07-13 (周四 23:30)

### 本次更新(中西医合集报告 + 西医分册)
**触发**:`cancer-weekly-research` + `cancer-tcm-weekly`(并行)

### 西医分册
- 新增 X 项
- ...

### 中医分册
- 新增 X 项
- ...

**笔记保存**
- 西医 note_id=**X**
- 中医 note_id=**Y**
- 合集 note_id=**Z**
```

## 异常条目

如果某次跑出现部分失败,在日志里用 ⚠️ 标出:

```markdown
## 2026-07-13 (周四 22:00)

### ⚠️ 本次更新部分失败
**触发**:`cancer-weekly-research` cron

- ✅ 报告文件已写入
- ⚠️ **Get笔记同步失败**:API 返回 401,token 过期
- ⚠️ **备份失败**:`backup/` 目录权限不足

下次跑时手动重新同步,详见 mavis-doctor 排查
```
