# 微信公众号文章章节配图整合技能

## 工作流程概览

1. 读取用户指定的文档，理解各章节内容与主题
2. 根据用户要求配图的章节进行配图
3. 将图片插入文档的（截图占位）的位置
4. 输出带图 Markdown 文件和word文件

---

## Step 1：读取文档

使用 `file` 工具读取用户上传的 `.docx` 文件，识别所有章节（通常以 `#01`、`#02` 等编号标识）。
可以参考references/reference_1008_research_methods.md

提取每章节的：
- 核心主题与关键信息
- 主要人物/场景（如"夜猫咖啡"、"小王"等）
- 情感基调（困惑、启发、反思等）
- 图片占位

---

## Step 2：创建工作目录

```bash
mkdir -p /home/ubuntu/{项目名}/
```

目录命名建议：使用文章主题的英文缩写，如 `stp_model`、`plc_model`、`service_quality_gap`。

---

## Step 3：批量生成章节配图

**核心原则：一次调用 `generate_image` 生成所有章节图片（最多5张/次）。**

### 图片生成要求

每张配图的 prompt 应包含：
- **场景描述**：与章节内容直接对应的具体场景
- **中文文字元素**：将章节中的关键词/金句嵌入图片（用中文显示）
- **视觉隐喻**：用图形化方式呈现抽象概念（如"差距"用鸿沟表示）
- **色彩方案**：与章节情绪匹配（问题章节用冷色调，解决方案用暖色调）
- **风格一致性**：同一文章的所有图片保持风格统一

### 各章节类型的配图策略

| 章节类型 | 配图策略 | 视觉元素 |
|---------|---------|----------|
| 问题引入（#00/#01） | 对比分裂画面，展示痛点 | 困惑人物、断裂的链条、鸿沟 |
| 案例推演（#02） | 信息图表/流程图风格 | 品牌Logo、流程箭头、数据可视化 |
| 模型介绍（#03） | 专业框架图 | 表格、层级结构、颜色编码 |
| 个人应用（#04） | 个人成长叙事场景 | 反思镜子、转变前后对比 |
| 总结升华（#05） | 哲学/启发性概念图 | 桥梁、光芒、金句文字 |

### 图片规格

- 格式：PNG
- 尺寸比例：`landscape`（16:9）
- 保存路径：`/home/ubuntu/{项目名}/chapter{编号}.png`
- 体积：小于2MB

---

## Step 4：编写 Markdown 文档

### 文档结构模板

```markdown
# 【日期】读书分享《营销管理》（第16版）：{标题}

{文章开头引入段落，保持原文}

---

## #01 {章节标题}

![{章节主题}配图](chapter01.png)

{章节原文内容，保留完整文字}

---

## #02 {章节标题}

![{章节主题}配图](chapter02.png)

{章节原文内容}

...（以此类推）
```

### 格式规范

- 图片引用使用**相对路径**（`chapter01.png`，不含目录前缀）
- 图片放置在章节标题**正下方**、正文**之前**
- 保留原文的所有内容，不删减、不改写
- 使用 Markdown 格式化：`**加粗**` 用于关键词，`>` 用于金句引用，`|表格|` 用于模型对比

### 文件命名

**严格保持原始文件名**，仅将扩展名从 `.docx` 改为 `.md`：
- 原文件：`【0409】读书分享《营销管理》（第16版）：不要你以为，要用户以为——服务质量差距模型.docx`
- 输出文件：`【0409】读书分享《营销管理》（第16版）：不要你以为，要用户以为——服务质量差距模型.md`

---

## Step 5：交付结果

使用 `message` 工具的 `result` 类型，附件顺序：
1. Markdown 文档（最重要）
2. 各章节配图（按 chapter01、chapter02... 顺序）
3. 插入到（插图占位）位置
4. 整合成一份WORD文档

回复格式示例：
```
已完成任务！为每个章节生成了精美配图并整合到文档中，保持了原文件名。

**生成的配图包括：**
- 章节01：{简述图片内容}
- 章节02：{简述图片内容}
...
```

---

## 注意事项

- 若章节超过5个，分两次调用 `generate_image`（前5章一次，剩余章节一次）
- 图片 prompt 必须用**英文**撰写，但可包含中文文字元素描述
- 每篇文章的"夜猫咖啡"案例章节（通常是#02）适合使用信息图/流程图风格
- 模型框架章节（通常是#03）适合使用专业表格+架构图风格
- 个人应用章节（通常是#04）适合使用手绘/叙事风格，增加亲切感
